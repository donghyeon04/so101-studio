# 배포·공개 준비 점검표

상태: 초안 · 2026-11-14 (기획 총정리. 마무리 주(11/30~12/4)에 이 표대로 한 번 돌리고, 그 전에는 항목이 생길 때마다 미리 맞춘다)

레포를 공개하거나 시연용으로 남기기 전에, 깨끗한 PC에서 README대로 동작하고 레포에 노이즈·개인 정보가 없는지 확인한다. 결과는 표의 "확인" 칸에 날짜와 커밋을 적는다.

## A. 레포 위생
| 항목 | 기준 | 확인 |
|---|---|---|
| 브랜치 | 원격에 `main`, `planning-inbox`(기획 요청함), 기획 승인 대기 브랜치만. 합쳐진 `dev/*`는 지운다. 지우기 전에 그 브랜치를 쓰는 worktree 폴더를 `main`으로 돌리고, `gh pr merge --delete-branch`는 쓰지 않는다(`session-workflow.md` 2절) | |
| 로컬 폴더 | 세션 폴더 넷 모두 `main`(또는 진행 중인 `dev/*`)이고 `git status`가 깨끗하다. 추적 안 한 결과 파일은 `runs/`로 옮기거나 지운다 | |
| git 제외 | `config/local.yaml`, `runs/`, `config/ultrasonic_baseline.json`, 캐시·빌드 산출물이 `.gitignore`에 있다 | |
| PC별 값 | 공통 설정(`config/robot.yaml`)에 COM 번호 같은 PC별 값이 없다(지금 `port: COM3`이 남아 있음 → `local.yaml`로) | |
| CAD 파일 | 3D·충돌에 쓰는 STL만 `assets/` 아래에 출처·라이선스와 함께 둔다. STEP 원본은 레포 밖(팀 드라이브)에 둔다 | |
| 문서 | 모든 문서가 `docs/README.md` 색인에 있고 상태 줄이 맞다. 대체된 결정은 상태 줄에 대체 번호가 있다 | |

## B. 깨끗한 PC 설치 시험 (팀원 PC 1대, 한글 사용자 폴더 포함)
| 순서 | 기준 | 확인 |
|---|---|---|
| 1 | `git clone` → `설치.cmd`가 끝나고 `doctor`가 실패 없이 나온다 | |
| 2 | `시뮬레이션 실행.cmd`로 GUI가 열리고 작업 공간 자동 실행이 끝까지 돈다 | |
| 3 | MuJoCo 설치 줄(`tooling-setup.md` C24) 뒤 `so101.cmd --sim --sim-engine mujoco gui`가 열린다 | |
| 4 | 실물 팔이 있으면 `실물 팔 실행.cmd`로 연결되고 캘리브레이션이 다르면 잠긴다 | |
| 5 | 걸린 시간과 막힌 곳을 README "빠른 시작"에 반영한다 | |

## C. 시험과 코드
| 항목 | 기준 | 확인 |
|---|---|---|
| 전체 시험 | `python -m pytest -q` 전부 통과(실행 시간과 통과 수를 적는다) | |
| 린트 | `python -m ruff check src tests` 0건 | |
| 안 쓰는 코드 | 옛 명령·옛 설정 키·지워진 기능의 남은 코드가 없다(예: 옛 `jog`를 남길지 정한다) | |

## D. 공개 문서
| 항목 | 기준 | 확인 |
|---|---|---|
| README | "지금 상태"가 마지막 실물 결과와 맞고, 빠른 시작·명령줄 표가 실제와 같다 | |
| 라이선스 | `LICENSE`(MIT)와 가져온 자산의 출처·라이선스(`assets/**/NOTICE`, `SOURCE.md`)가 있다 | |
| 개인 정보 | 이메일·토큰·개인 경로가 코드와 문서에 없다(팀원 이름은 README 팀 줄만) | |
| 버전 | 시연 커밋에 태그(예: `v1.0-demo`)를 달고, 기능·알려진 한계를 짧게 적는다 | |
