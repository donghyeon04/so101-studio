## B. 깨끗한 PC 설치 시험 (팀원 PC 1대, 한글 사용자 폴더 포함)
| 순서 | 기준 | 확인 |
|---|---|---|
| 1 | `git clone` → `설치.cmd`가 끝나고 `doctor`가 실패 없이 나오며, 바탕화면·시작 메뉴에 "SO-101 Studio" 바로가기가 생긴다 | |
| 2 | 팔 없이 바로가기(`SO-101 Studio 실행.cmd`)로 켜면 켤 때 `git pull --ff-only`를 하고, GUI가 시뮬레이션으로 열려 안내를 띄우며, 작업 공간 자동 실행이 끝까지 돈다 | |
| 3 | `설치.cmd`의 MuJoCo 질문에 Y(`tooling-setup.md` C24, numpy 2.2.6 확인) 뒤 `so101.cmd --sim --sim-engine mujoco gui`가 열린다 | |
| 4 | 실물 팔이 있으면 같은 바로가기로 연결되고 캘리브레이션이 다르면 잠긴다 | |
| 5 | `제거.cmd`: `yes` 전에는 아무것도 지우지 않고, 환경·바로가기를 지우며, 레포 폴더는 남기고 안내한다. Miniforge는 `설치.cmd`가 깐 표시 파일(`C:\so101-tools\installed-by-so101.txt`)이 있을 때만 한 번 더 묻는다 | |
| 6 | ZIP으로 받은 폴더(`.git` 없음)에서도 1·2가 되고, 실행 때 업데이트만 건너뛴다 | |
| 7 | 걸린 시간과 막힌 곳을 README "빠른 시작"에 반영한다 | |

## E. 최종 배포 (설치 프로그램, 사용자 결정 2026-11-19)
v0.1은 배치 파일 셋으로 낸다. Inno Setup 설치 프로그램(`Setup.exe`)은 최종 배포 단계에서 만든다.
| 항목 | 기준 | 확인 |
|---|---|---|
| 같은 일 | 지금 `설치.cmd`가 하는 일(Miniforge·git·`so101` 환경·MuJoCo 물음·바로가기·`doctor`)을 그대로 한다 | |
| 제거 | Windows "앱" 목록에 등록되고, 제거가 `제거.cmd`와 같은 것을 지우고 같은 것을 남긴다 | |
| 업데이트 | 설치 폴더가 git 폴더가 아니면 실행 때 업데이트를 어떻게 하는지(새 Setup.exe 또는 git) 정해 README에 적는다 | |
| 시험 | B절 1~7을 Setup.exe로 다시 한다 | |

시연 당일 하드웨어 순서는 `real-arm-runbook.md`를 따른다.
