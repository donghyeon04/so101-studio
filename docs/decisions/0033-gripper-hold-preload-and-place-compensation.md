# 0033. 그리퍼는 접촉 뒤 예압으로 잡고, 조임 한계는 RAM으로, 들고 있는 동안은 과부하 기준 아래로, 놓을 때도 중심을 맞춘다

상태: 확정 · 2026-11-04 (0010~0012 보완)

## 맥락
GUI 실물 시험(run 20261104-013923)에서 그리퍼가 물체를 문 채 더 조여 과부하 오류(id 6)가 났다. 원인은 셋이다.
- 접촉으로 멈춘 뒤에도 명령값이 실제보다 닫힌 쪽에 남아 서보가 계속 민다.
- 접촉 뒤 조임 한계를 500으로 되돌린다. 이 한계는 EEPROM 레지스터 `Max_Torque_Limit`(16번)에 쓰고 있었다.
- 연결 때 쓰는 그리퍼 `Overload_Torque` 25%를 넘는 힘이 보호 시간 넘게 이어진다.
놓을 때는 그리퍼가 열리는 동안 손이 고정이라 물체가 밀린다. 팔 세션의 기획 요청을 검토한 결정안을 사용자가 승인했다.

## 결정
- 접촉하면 그리퍼 목표를 "지금 위치 + 예압 `grip_preload_units`(기본 2)"로 바꾼다. 조이는 힘은 위치 오차만큼으로 제한된다.
- 조임 한계는 RAM `Torque_Limit`(48번)으로 바꾸고 EEPROM에 쓰지 않는다. 닫는 동안은 `gripper_squeeze_torque`(300), 들고 옮기는 동안은 `gripper_hold_torque`(200, 과부하 기준 25% 아래), 놓은 뒤에는 원래 값으로 되돌린다.
- `no_object`이면 접근 높이까지 올라온 뒤 `gripper_open`으로 연다. 바닥에서는 열지 않는다.
- 그리퍼 부하 감시는 두 단계다. 기준을 넘으면 먼저 목표를 지금 위치로 맞춰 조임을 멈추고 WARN을 남긴다. 그래도 이어지면 그리퍼를 열고 fault를 낸다. 기준은 정상 집기 5회의 부하 최대값의 1.3배, 지속 1초로 시작해 설정값(`gripper_load_warn_pct`, `gripper_load_s`)으로 둔다.
- 놓을 때는 집을 때의 닫는 경로(`_closing_path`)를 반대로 써서, 그리퍼가 열리는 동안 두 턱의 중간점이 물체 위에 머물게 손을 같이 보낸다.
- 구현은 팔 세션(REQ-020)이 한다. 효과는 실물로 확인한다(집기 5회, 놓기 5회, 그리퍼 부하와 과부하 오류 기록).
