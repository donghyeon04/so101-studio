# 0044. GUI는 지금 구조를 고쳐 쓰고, 다음 기능은 블록 프로그래밍·캘리브레이션 마법사·장면 부품 편집기

상태: 확정 · 2026-11-07 (사용자가 로컬 총괄과 정함, 0043-5의 기능 순서를 대체. MuJoCo 방식 → 0053)

## 맥락
GUI 형식·구성을 레퍼런스(Universal Robots PolyScope X, MoveIt Pro 웹 UI, Foxglove, phosphobot·LeRobot 흐름, Carbon)와 비교했다. 지금의 "왼쪽 메뉴 + 위 상태줄 + 항상 보이는 E-STOP"은 PolyScope X·MoveIt Pro와 같은 뼈대다. 패널을 끌어 배치하는 Foxglove 방식은 분석 도구용이라 우리 용도에 과하다. 0043-5의 기능 후보 13개도 사용자가 다시 정리했다.

## 결정
1. **GUI 구조는 유지하고 고친다.**
   - 아래 고정 팔 조작 막대(속도·E-STOP·정지 해제·홈)를 둔다.
   - 어느 화면에서나 여는 조그 패널을 둔다.
   - 자주 쓰는 자세 목록과 즐겨찾기를 둔다.
   - 블록 프로그래밍은 프로그램 트리 화면으로 만든다(작업 메뉴 아래).
   - 시연용 운영자 화면을 만든다. 읽기 전용 보기는 여기에 묶는다(다른 기기 접속 주소 안내, 조작 버튼 숨김).
   - 메뉴를 정리한다: 카메라 화면은 카메라를 달 때까지 숨기고, 캘리브레이션 마법사는 장치 › 팔 아래에 둔다.
2. **할 기능**: 블록 프로그래밍(7), 캘리브레이션 마법사(9), 장면 부품 편집기(12, 원본 STEP을 받은 뒤 쓸모가 크다). 그다음 MuJoCo 물리 시뮬레이션(5)을 한다.
3. **뺄 기능**: LeRobot 데이터셋·Hub 업로드(1), 리더 팔(2), 실물 게임패드(3), Foxglove/Rerun 내보내기(11).
4. **카메라를 단 뒤**: 비교 실험 실행기(10), 학습 정책 실행(4). 정책 실행에는 카메라, 시연 40~50회, GPU가 필요하다.
5. 직접 설계 부품(레이더 스테이션, 그리퍼 개조, 손목 초음파 브래킷)은 STEP을 받기 전까지 임시 상자로 둔다.

## 결과
- GUI 순서: 메뉴 정리 → 조작 막대·조그 패널 → 자세 목록·프로그램 트리 → 캘리브레이션 마법사 → 운영자 화면 → 장면 부품 편집기 → MuJoCo.
- `gui-spec.md`의 해당 절은 화면을 만들 때마다 고친다.
