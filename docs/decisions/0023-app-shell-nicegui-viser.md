# 0023. GUI는 완성형 앱: NiceGUI로 앱 틀, Viser로 3D, 센서별 화면을 끼워 넣는 구조

상태: 확정 · 2026-11-02 (다른 기기 보기 `--share` 예외 → 0047)

## 맥락
0021은 Viser 하나로 GUI를 만들기로 했다. 그런데 PIPER Studio의 실제 화면(사이드바 그룹 메뉴, 페이지별 카드, 상태줄, 모든 화면의 E-STOP)을 참고해 보니, Viser의 "3D 화면 하나와 떠 있는 패널" 구조로는 그런 앱을 만들 수 없다. 이 프로그램은 발표용 데모가 아니라 그 자체로 완성된 앱이어야 하고, 초음파 다음에는 카메라 같은 센서를 더 붙일 수 있어야 한다.

## 결정
- 앱의 틀(사이드바, 페이지, 카드, 그래프, 상태줄, 테마)은 NiceGUI로 만든다. 3D(URDF 팔, 계산 자세, 클릭으로 점 찍기, 끌기 손잡이)는 Viser가 맡고 페이지 안에 넣는다. 둘 다 같은 Python 프로세스에서 `ArmService`·`Studio`를 호출한다. 실행은 `so101 gui`, 화면은 브라우저에서 연다.
- 앱은 완성형 프로그램으로 만든다. 청중만을 위한 기능(설명 카드, 설명 수준, 글씨 크기 전환)은 넣지 않는다. 발표는 이 앱을 그대로 프로젝터에 띄우고 직접 조작하면서 한다.
- 센서는 끼워 넣는 구조로 만든다. 인식 방식(`PerceptionSource`)마다 자기 화면(센서가 바라보는 세상)을 하나씩 등록하고, 앱은 등록된 화면을 메뉴에 붙인다. 초음파는 작업대 평면 2D(스캔 부채꼴, 각도별 거리, 찾은 물체)로 보여 준다. 카메라는 나중에 같은 방식으로 추가한다.
- 시뮬레이션과 실제의 실행 방식(동시 / 시뮬레이션 먼저 하고 확인 / 시뮬레이션만 / 실제만)은 설정값으로 고른다.
- 여러 브라우저가 접속해도 조작은 한 곳만 하고, 나머지는 보기만 한다. 공유 링크는 시뮬레이션에서만 연다.
- 0021의 나머지 결정(실제·미리보기 팔 두 개, 기구학 쌍둥이, 연결이 끊기면 `stop()`, UFACTORY 화면 참고)은 그대로 유지한다.
