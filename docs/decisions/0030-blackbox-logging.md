# 0030. 상태·이벤트 기록은 JSON Lines 블랙박스로: 공통 머리, 토크·fault 기록, 링 버퍼, 사고 묶음

상태: 확정 · 2026-11-04

## 맥락
2026-11-04 사고(0° 자세에서 GUI를 실제 팔로 켜자 토크가 풀려 팔이 주저앉음)를 기록으로 되짚지 못했다. `status.csv`에는 토크·state·fault 칸이 없고, 상태 읽기 루프는 예외를 조용히 버리며, 토크 켜고 끄기와 레지스터 쓰기가 남지 않았다. 연결 뒤 6초가 비었고 프로세스별 기록은 흩어져 있었다. 레퍼런스 12개(PX4 logger, rosbag2 스냅샷 모드, MCAP, ROS 2 diagnostics, UR·ABB 이벤트 로그, PIPER Studio 등)를 조사했고 사용자가 결정안을 승인했다.

## 결정
- 형식은 JSON Lines를 유지한다. 모든 줄에 공통 머리 `t`(벽시계 ns)·`proc`·`pid`·`seq`·`level`(DEBUG~FATAL)·`code`·`kind`·`data`를 둔다. 프로세스마다 자기 파일에 쓰고, 화면은 `t`로 합쳐 한 시간축으로 본다. MCAP는 나중에 내보내기로만 검토한다.
- 상태(10Hz)에 관절별 토크·명령값·실제값·온도·부하·전류, `state`, `fault`와 이유, 서보 `Status` 비트, 전압, 누적 `time_lost_s`, 틱 간격 최대값을 더한다. 연결하자마자 첫 줄을 남긴다.
- 이벤트: 연결·해제, 토크 켜기·끄기(부른 함수 포함), 레지스터 쓰기(목표 위치 스트림 제외), fault, E-STOP, 감시 작동, 조작권·실행 방식·안전 설정 변경, 캘리브레이션 저장·확인, 예외(조용히 버리지 않음). 켜져 있어야 할 토크가 꺼져 읽히면 `ARM-TORQUE-LOST` ERROR.
- 제어 루프는 파일에 쓰지 않는다. 큐로 기록 스레드에 넘기고 줄마다 flush, WARN 이상은 fsync. 큐가 차면 상태 줄만 버리고 수를 센다.
- 50Hz 틱의 최근 10초를 메모리 링 버퍼에 두고, fault·E-STOP·감시 작동·예외 때 `runs/incidents/<시각>-<이유>/`에 사고 묶음(모든 프로세스 기록 앞뒤 60초, 링 버퍼, 설정·캘리브레이션 사본과 해시, doctor 결과, git 커밋·버전)으로 남긴다.
- 보관: 실행 기록은 30일 또는 2GB를 넘으면 오래된 것부터 지우고, 상태 파일은 50MB마다 나누며, 사고 묶음은 지우지 않는다.
- 추가 버스 읽기는 2Hz 묶음에만 붙인다. 5분 실행에서 `time_lost_s` 증가 1% 미만, 틱 간격 p99 증가 2ms 이하여야 한다.
- 기록은 팔 세션(REQ-018), 화면(구성 요소 상태, 합친 로그, 사고 목록)은 GUI 세션(G11)이 만든다.
