# 0002. 문서 구조와 보관 규칙

상태: 확정 · 2026-10-31

## 맥락
문서가 무분별하게 늘어나거나 비정형으로 쌓이면 사람에게는 찾기 어렵고, AI에게는 노이즈가 된다. 1회성 조사 기록은 결론이 반영된 뒤에는 다시 읽히지 않는다.

## 검토한 대안
- 조사 기록까지 `docs/references/`에 모두 보관하기
- 결정 기록을 `decisions.md` 한 파일에 모으기
- 문서 유형을 고정하고, 색인과 상태값을 두고, 결정마다 파일을 따로 두기 (MADR 방식)

## 결정
세 번째 안을 택한다.
- 문서 위치는 `README.md`, `docs/planning/`, `docs/decisions/`, `docs/guides/` 네 곳만 쓴다.
- 모든 문서는 `docs/README.md` 색인에 등록하고, 맨 위에 `상태: 초안 / 확정 / 대체됨(→ NNNN)`을 적는다.
- 결정 기록은 수정하지 않는다. 결정이 바뀌면 새 기록을 만들고 이전 기록의 상태를 "대체됨"으로 바꾼다.
- 기획 문서는 같은 파일을 계속 고친다. 이전 버전은 git이 보관한다.
- 조사 원문은 커밋하지 않고 대화에서만 쓴다.
- 단계가 바뀔 때마다 색인을 점검하고, 낡은 초안은 삭제한다.

근거: MADR 4.0, Anthropic "Effective context engineering for AI agents", Diátaxis, Kubernetes KEP 상태 모델, Rust RFC.
