# 0068. ACT 시연 수집을 다시 짠다: 좁힌 1차 묶음, 빠른 시연, action 앞당김 비교, 병렬 수집

상태: 확정 · 2026-11-18 (사용자 승인, 총괄 기획 요청 main ad29183. 결정 0066의 "성공률 목표는 두지 않는다"를 1차 묶음에 한해 바꾼다)

## 맥락
- REQ-072 ACT(시연 300개)가 학습 설정을 바꿔도 0/50·0/20이었다. 시연이 30~34초로 느리고, 프레임 16%가 정지해 있으며, action(그 틱의 명령)과 상태의 차이 중앙값이 0.29°다. 정책이 "지금 자세를 베끼기"를 배울 수 있다(copycat 문제).
- 원문 확인 레퍼런스(aviadarn/so101-lerobot): 시연 약 3초(50Hz), 상태보다 앞서는 절대 관절 목표, 상자 각도 무작위 없음. 300개 42~68%, 600개 + 이어 학습 88~92%. ACT 원본 스크립트 시연은 8초(50Hz)다.

## 결정
1. **1차 묶음을 좁힌다**: `collect_pick1`(이름은 구현이 정함)은 상자 한 면이 팔 방향과 나란한 각도로 고정하고, 반경 150~200mm·방위 ±30°로 한다. 성공하면 각도·범위를 넓힌다.
2. **시연을 빠르게 한 번 다시 모은다**: 에피소드 길이 중앙값 10초 이하, 판정 대기 0.3초. sim 수집 전용 프리셋으로 하고 안전 검사는 끄지 않는다.
3. **action 앞당김은 같은 데이터로 비교한다**: 기록은 그 틱의 명령 그대로 두고, `action[t] = cmd[t+k]`로 민 사본을 만들어 k=0과 k=5(0.2초)를 학습해 비교한다.
4. **시작 자세는 바꾸지 않는다**(`radar_clear` 그대로). 위 카메라가 늘 상자를 본다. 두 변형이 모두 실패하면 다시 본다.
5. **다음 단계 기준**: 처음 보는 씨앗 50개 중 15개(30%) 이상 `placed_ok`. 못 넘으면 시연 600개·이어 학습을 한 번 더 하고, 11/23 범위 점검에서 L3·L4를 자를지 본다.
6. **수집과 평가는 병렬로 돈다**(`--jobs N`, M5와 같음). 일꾼마다 데이터셋 조각을 쓰고 끝에 합친다. `realtime_lag`가 난 에피소드는 저장하지 않는다.
7. 스크립트 전문가는 실제 작업 실행과 같은 `Skills.pick`·`place` 규칙을 쓴다. 집기 규칙이 바뀌면(결정 0069) 시연도 따라 바뀐다.
