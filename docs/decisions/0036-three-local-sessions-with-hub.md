# 0036. 로컬 세션을 GUI(총괄)·팔·초음파 셋으로 나누고, GUI 세션이 일을 나누고 요청 대장을 관리한다

상태: 확정 · 2026-11-05 (0024 보완)

## 맥락
결정 0024는 로컬을 GUI 세션과 팔 세션으로 나눴다. 초음파 인식(결정 0034)은 펌웨어와 인식 코드라는 새 영역이고, 팔 세션은 실물 시험과 REQ가 남아 있다. 사용자는 주로 한 세션과 이야기하며 일을 시키고 싶어 했고, 아래 구성을 승인했다.

## 결정
- 로컬 세션은 셋이다.
  - GUI 세션(Opus): GUI 구현에 더해 로컬 총괄을 맡는다. 폴더는 `so101-studio-gui`.
  - 팔 세션(Sonnet): 폴더는 `so101-studio`.
  - 초음파 세션(Sonnet): 폴더는 `so101-studio-us`. `src/so101_studio/perception/ultrasonic/`, `firmware/`, `tests/perception/`, `config/ultrasonic.yaml`, `docs/planning/us-dev-status.md`만 고친다.
- 총괄이 하는 일:
  - 사용자 지시를 쪼개 각 세션에 보낸다. `SendMessage`가 안 되면 붙여 넣을 프롬프트를 사용자에게 준다.
  - `session-requests.md`를 관리한다.
  - Sonnet 세션의 PR을 합치기 전에 검토한다. 안전에 걸리는 코드는 줄 단위로 본다.
  - 설계 변경은 [기획 요청]으로 모아 사용자에게 올린다.
- 총괄도 자기 영역(`gui/`, `tests/gui/`) 밖의 코드는 고치지 않는다. 설계서와 결정 기록은 지금처럼 기획 세션만 고친다.
- 진행 상황은 대화가 아니라 요청 대장과 각 세션의 현황 문서에 남긴다. 그래야 압축 뒤에도 이어진다.
