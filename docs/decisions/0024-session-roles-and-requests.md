# 0024. 로컬 개발은 GUI 세션과 팔 세션으로 나누고, 서로 요청서로 일을 주고받는다

상태: 확정 · 2026-11-02

## 맥락
팀 검토에서 GUI는 "기본 골자를 먼저 만들고, 기능은 나중에 붙일 수 있게 확장성을 둔다"로 승인됐다. GUI를 만들다 보면 팔 쪽 코드(`ArmService`, `Studio`, 인식)를 고쳐야 할 일이 생긴다. 하지만 한 세션이 GUI와 팔 코드를 같이 고치면 범위가 섞이고 실제 팔 동작이 깨질 위험이 있다.

## 결정
- 로컬 개발은 두 세션으로 나눈다. **GUI 세션**은 `src/so101_studio/gui/`, `tests/gui/`만 고친다. **팔 세션**은 그 밖의 `src/`, `config/`, `tests/`를 고친다. 기획 세션(원격)은 문서만 고친다.
- 두 세션은 같은 PC에서 git worktree로 폴더를 나눈다. 브랜치는 `dev/gui-*`, `dev/arm-*`이고, 각자 PR로 `main`에 합친다.
- GUI 세션은 팔 코드가 필요하면 직접 고치지 않는다. 요청서(REQ)를 팔 세션에 직접 보낸다(Claude Code 세션 간 메시지, 안 되면 사용자가 붙여 넣기). 기다리는 동안에는 `gui/backend.py` 안에서 임시로 우회하고, 우회한 곳에 `REQ-NNN` 표시를 남긴다.
- 기존 동작을 바꾸지 않고 함수만 더하는 요청은 팔 세션이 바로 처리한다. 기존 API를 바꾸거나 설계가 달라지는 요청은 멈추고 기획 세션(사용자)에게 올린다.
- 요청은 받은 세션이 `docs/planning/session-requests.md`에 기록하고 상태를 갱신한다. 절차와 양식은 `docs/guides/session-workflow.md`에 있다.
- 실제 팔(COM3)과 ESP32 포트는 한 번에 한 세션만 연다. 열기 전에 다른 세션에 알린다.
