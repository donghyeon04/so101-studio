# 0037. 검증용 계산기는 주제마다 하나만 두고, 레포 안 실제 코드 위에서 돌린다

상태: 확정 · 2026-11-05

## 맥락
초음파 확인 방식의 성능(성공률, 시간)을 두 계산기가 따로 냈다. 하나는 기획 세션이 조사용으로 따로 짠 스크립트이고(레포 밖), 다른 하나는 초음파 세션이 레포에 만든 가상 ESP32와 가상 팔이다. 가정이 서로 맞지 않아 결과가 크게 달랐다. 물체 3개에서 78~93%와 약 2/3이었고, 시간 모델도 달랐다. 기획 쪽은 정지·가속 비용을 빠뜨렸고, 성공 판정이 너그러웠으며, 배치 간격과 도달 제한도 달랐다. 사용자는 앞으로 검증할 것이 있으면 도구를 하나만 만들고 거기에 아이디어를 붙이는 방식을 원했다.

## 결정
- 검증용 계산기·시뮬레이터는 주제마다 하나만 둔다. 레포 안에 두고, 실제로 쓸 코드를 그대로 돌린다. 지금 정해진 것은 두 가지다.
  - 초음파 성능은 초음파 세션의 가상 ESP32 + 가상 팔 벤치마크(`ultrasonic-spec.md` 8.5절).
  - 팔 도달 범위는 팔 세션의 도달 계산(REQ-023).
- 새 아이디어나 선택지는 그 도구의 옵션이나 시나리오로 붙인다. 다른 세션이 같은 주제의 계산기를 따로 만들지 않는다. 기획 세션도 따로 계산하지 않는다.
- 기획 세션은 가정(센서 모델 값, 배치, 판정 규칙, 시나리오)을 설계서에 정하고, 결과가 그 가정대로 나왔는지 검토한다. 계산은 그 도구를 맡은 세션이 총괄을 거쳐 돌린다.
- 설계서에 적는 성능 숫자는 그 도구의 고정 시나리오 결과만 쓰고, 커밋과 시나리오 이름을 출처로 함께 적는다.
- 실측(B1~B3, R1, A1, I1 등)이 나오면 가상 값보다 실측을 따르고, 도구의 모델 값을 실측으로 고친다.
- 지금까지 기획 세션의 조사용 계산으로 적은 숫자는 "기획 초기 계산(참고)"로 표시하고, 벤치마크 결과가 나오면 바꾼다.
