# 0027. 팔별 값은 보드 시리얼로 고르는 팔 파일에, PC별 값은 git에 올리지 않는 local.yaml에 둔다

상태: 확정 · 2026-11-03

## 맥락
GUI 세션의 기획 요청: 다른 PC나 다른 팔에서 바로 쓸 수 없다. `robot.yaml`에는 포트(COM3) 같은 PC 값과, 이 팔에서 잰 영점·관절 한계·작업대 높이 같은 팔 값이 섞여 있다. 그래서 다른 팔에 그대로 쓰면 위험하고, `so101.cmd`는 이 PC의 경로에 맞춰져 있다. 레퍼런스: LeRobot은 팔 이름별 캘리브레이션 파일과 USB를 뺐다 꽂아 포트를 찾는 방식, PIPER Studio는 USB 어댑터 고유 ID(by-id)를 팔의 정체로 보고 그 키로 설정을 저장한다.

## 결정
- 설정은 세 겹이다. `config/robot.yaml`(모든 SO-101 공통 기본값) ← `config/arms/<팔 이름>.yaml`(팔별 값, git에 올림) ← `config/local.yaml`(PC별 값, git 제외, `local.example.yaml`을 올림). 뒤의 값이 앞의 값을 덮는다.
- 팔 파일에는 보드 USB 시리얼, 캘리브레이션 ID, 영점, 관절 한계, 실제 가동 범위, 작업대 높이, 그리퍼 폭 표, 집기 보정을 둔다. 지금 팔은 `arms/so101_follower_01.yaml`이다.
- 팔 고르기 순서: `--arm` 옵션 → `local.yaml`의 `arm` → 연결된 보드 시리얼과 같은 팔 파일 → 팔 파일이 하나뿐이면 그것 → 못 고르면 멈추고 물어본다. 포트 순서: `--port` → `local.yaml`의 `port` → 보드 VID·PID와 시리얼로 자동 찾기 → 여러 개면 묻고, 못 찾으면 `so101 find-port`(LeRobot처럼 뺐다 꽂아 찾기).
- 보드 시리얼은 맞는데 서보의 캘리브레이션 값이 팔 파일과 다르면(보드를 다른 팔로 옮긴 경우) 움직이는 명령을 막고 읽기만 허용한다. 팔 파일이 없는 새 팔도 캘리브레이션과 팔 파일을 만들기 전에는 움직이지 않는다.
- `so101 doctor`는 읽기 전용 점검이다. 환경, 패키지, 포트, 고른 팔 파일, 캘리브레이션 대조, 서보 응답, 전압·온도를 정상/주의/실패로 보여 주고 `--json`으로 GUI에 준다. 팔을 움직이거나 EEPROM에 쓰지 않는다.
- 설치는 `environment.yml`(conda)로 하고, 런처는 고정 경로 대신 conda 환경 이름으로 찾는다. Windows는 `so101.cmd`, Linux는 `so101.sh`(시리얼 권한 안내 포함)를 쓴다.
- 구현은 팔 세션(REQ-015)이 한다. GUI는 장치 > 팔 페이지에 점검 결과, 고른 팔 파일, 새 팔 안내를 보여 준다.
