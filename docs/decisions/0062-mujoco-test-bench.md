# 0062. MuJoCo를 시험장으로 키운다: 공통 층 하나 위에 우리 알고리즘과 (나중에) 강화학습 실행기

상태: 확정 · 2026-11-14 (사용자 승인, `researching-references`로 후보 24개 비교. 0053의 우선순위 조건과 0037의 적용을 구체화한다) · 3번의 "M9 강화학습(12/4 뒤)" 가운데 so101-nexus 환경의 학습 데모와 5번 GUI 잠금 일부는 0066이 바꾼다

## 결정
1. **구조**: 시험장은 공통 층 하나(세계 짓기·센서·판정·기록, Gymnasium 꼴 겉모양)다. 그 위에 실행기 A(우리 알고리즘, `ArmService` 위)를 지금 만들고, 실행기 B(강화학습)는 12/4 뒤에 붙인다. 학습 틀은 새로 만들지 않고 가져온다(so101-nexus·mjlab 평가 뒤).
2. **도구 하나(0037)**: 물리 집기·놓기 성공률과 부품 사전 평가는 이 시험장 하나로 잰다. 알고리즘 비교는 옵션으로 붙인다. 초음파 성능은 기존 벤치마크에 MuJoCo 엔진 옵션을 더한다.
3. **순서**: M7a 부품 사전 평가(지금) → M5 집기 시험장·M6 초음파를 MuJoCo에 → M5b 빠른 모드·M5c 서보 맞추기 → M8 GUI 시험장 → M9 강화학습(12/4 뒤). 세부는 `arm-software-spec.md` 13.10.
4. **우선순위(0053 조건 대체)**: 필수 경로에 실물 작업이 있으면 실물이 먼저다. 하드웨어를 기다리는 동안은 시험장이 정식 작업이다. 11/30부터 새 기능은 멈춘다.
5. **GUI 잠금**(`gui-spec.md` 12.8의 시나리오 거부·물체 편집 거부)은 M8 전까지 유지하고, M8에서 "바꾸면 세계를 다시 짓는다"로 푼다.
6. **강화학습으로 넘기는 문턱**: 어떤 물체 묶음이 시험장에서 목표 성공률에 못 미치고, 옵션을 바꿔도 오르지 않으며, 원인이 구조 한계면 M9 후보로 올린다. 실물로는 시뮬레이션 체크포인트에서 시작해 실물에서 이어 배운다(HIL-SERL).
