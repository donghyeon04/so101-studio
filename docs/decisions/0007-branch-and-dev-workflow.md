# 0007. 브랜치 전략과 개발 세션 작업 흐름

상태: 확정 · 2026-11-01

## 맥락
기획 문서는 기획 세션 브랜치에만 있다. 로컬 개발 세션이 같은 기준 문서에서 출발하고, 개발 결과(측정값, 설계와 다른 점)가 기획으로 돌아오는 경로가 필요하다.

## 결정
- 기획 세션 브랜치를 PR로 `main`에 합친다. `main`이 기획 문서와 코드의 기준이다.
- 개발은 `main`에서 `dev/<작업>` 브랜치(예: `dev/arm-t0-t7`)를 따서 하고, 끝나면 PR로 `main`에 합친다.
- 기획 세션은 합쳐진 `main`에서 새로 출발한다.
- 개발 세션은 측정값을 `docs/planning/measurements.md`에 기록한다.
- 설계서와 다르게 구현해야 하면 개발 세션은 멈추고 사용자에게 알린다. 설계서는 기획 세션에서 고친 뒤 진행한다.
