## 2. 항목별

### F1 홈 자세(그리퍼별)
- 지금 `poses.home`은 `config/robot.yaml`의 `[0, -90, 93, 0, 0, 3]` 하나다(wrist_roll 0).
- `config/grippers/parallel.yaml`에 `poses`를 넣고 home의 wrist_roll만 90으로 둔다. 설정 겹은 키 단위로 통째로 바꾸므로(arm-software-spec 7.1) `park`·`radar_clear`도 같은 값으로 함께 적는다. 단동식은 그대로다.
- **에피소드 시작 자세는 바꾸지 않는다**: MuJoCo 드라이버 시작(`mujoco_driver.py`), 세계 다시 짓기·수집·정책 실행, 초음파 벤치마크 가상 팔(`benchmark.py`)이 지금 `poses.home`을 쓴다. ACT v2는 wrist_roll 0 시작으로 학습했고, 비교 실험 (가)(나) 숫자도 그 자세에서 냈다. 그래서 새 키 `poses.episode_start`(없으면 `home`)를 두고 `parallel.yaml`에 옛 home을 적는다. 이 세 곳은 `episode_start`를 읽는다.
- 확인: GUI 3D 스크린샷(병렬 홈에서 두 턱이 양옆), MuJoCo 정책 실행 씨앗 몇 개가 전과 같은 결과, `pytest` 빠른 묶음.
- 영역: 팔(`config/grippers`, 벤치마크 쪽 한 줄은 초음파 세션에 같이 알림), MuJoCo(드라이버·다시 짓기).

### F4 극한 자세에서 홈 우회
- 지금 `Skills.home`은 관절 보간 한 번이다. 경로가 바닥·장면 부품·작업 영역에 걸리면 `out_of_bounds`로 거부된다. 사용자 사례는 손끝 (132, 30) 높이 7mm(베이스 바로 앞 바닥 근처)다.
- 바꾸기(arm-software-spec에 적는다):
  1. 바로 가는 관절 이동을 먼저 검사한다. 되면 그대로 간다(지금과 같다).
  2. 거부되면 지금 손끝 xy에서 손 자세를 유지한 채 수직으로 `home_lift_mm`(작업대 면 위 80mm, 설정) 높이까지 올린다. 지금 자세가 이미 범위 밖이면 범위 안쪽으로 돌아오는 방향은 허용한다(`check_goal(ref=)`와 같은 규칙을 경로에 쓴다).
  3. 거기서 홈으로 관절 이동한다.
  4. 그래도 안 되면 지금처럼 멈추고 "직접 조작으로 위로 빼 주세요"를 이유와 함께 낸다.
- 이벤트 `ARM-HOME-DETOUR`(INFO: 올린 높이, 첫 거부 이유). 방금 놓은 상자를 쓰는 검사(`home_blocked`)는 그대로 앞에 둔다.
- 시험: 사용자 사례 자세에서 `--sim` 홈이 우회로 성공, 우회가 필요 없는 자세는 이동이 한 번, 올리기도 막히는 자세는 `stopped`.
- 영역: 팔(`arm/skills.py`, `service`, 시험). GUI는 메시지를 그대로 보인다.

### F5 교시 기록의 그리퍼 태그
- `config/sequences/<이름>.json`의 `meta`에 `gripper`(`cfg.gripper`)를 더한다. 그리퍼 값 0~100은 그리퍼마다 폭이 달라서다.
- `info`와 GUI 교시 목록에 태그(병렬 / 단동식 / 모름)를 보인다. 옛 기록은 "모름"이다.
- 재생할 때 지금 그리퍼와 태그가 다르면 GUI는 확인 창을 띄우고, CLI는 거부한 뒤 `--any-gripper`로만 돈다. "모름"은 경고만 한다.
- 영역: 팔(`arm/teach.py`, CLI), GUI(교시 목록·재생 확인).

### F9 안전 화면
- 3D를 돌리면 배출 구역이 사라지는 문제: 구역 판이 작업대 면 바로 위(z 1mm, 두께 1mm)에 있고 반투명 안전 상자와 겹쳐 그려진다. 각도에 따라 깊이 순서가 바뀌는 것으로 보인다. GUI 세션이 원인을 확인하고 고친다(구역을 조금 띄우기, 안전 상자는 모서리 선 + 옅은 면으로).
- 높이 범위: 코드 기본은 이미 아래만 있다(`Safety.box`의 z = [`z_floor_mm` 4, 없음]). 화면이 그것을 안 보여 주는 것이 문제다. 추천: 아래쪽 바닥 보호는 남기고 위쪽은 기본 없음(지금 코드). GUI는 "높이 최대: 없음(비움)"으로 보이고, 3D 상자는 위쪽을 열린 모양(점선 윗면)으로 그린다. 입력 상한 500mm는 그대로 두고 비움을 기본으로 한다. 최소는 바닥 보호 아래로 못 내린다(끄려면 지금처럼 모드 "끔").
- 영역: GUI(`pages/safety.py`, `scene3d.py`). 팔 쪽 변경 없음.

### F6 3D에서 집어 옮기기
- 지금 `backend.pick_place`와 직접 조작의 "집어 옮기기" 카드가 있다. 하지만 3D를 찍어 좌표를 넣은 뒤 [지금 좌표를 집기 점으로]·[놓기 점으로]를 따로 눌러야 한다.
- 바꾸기: 카드에 "3D에서 찍기: 집기 점 / 놓기 점" 토글을 둔다. 켠 동안 다음 3D 클릭이 그 점을 바로 정한다. 3D에 집기 점(주황)·놓기 점(초록)과 둘을 잇는 점선을 그린다. 수동 물체를 찍으면 그 물체의 폭·길이·각도·높이를 칸에 채운다. 놓기 점이 없으면 지금처럼 배출 구역이다.
- 영역: GUI(`pages/manual.py`, `scene3d.py`). 팔 API는 그대로다.

### F3 기구학 시뮬레이션에서 쥔 상자 따라가기
- 지금 기구학 엔진에는 물리가 없다. 상자는 수동 물체 목록대로 제자리에 그려지다가 집기 성공 뒤 목록에서 빠질 때(놓을 때) 사라진다.
- 추천: 기구학 엔진에서는 쥔 물체를 손끝에 붙여 그린다. MuJoCo 엔진은 이미 물리로 움직이므로 그대로 둔다.
  - 팔: `ArmService.held`(쥔 물체 `DetectedObject`, 닫을 때 손끝 기준 물체 자세)를 두고, 집기 성공 때 채우고 놓기에서 벌리기 시작할 때 비운다. 이벤트 `ARM-HELD`(잡음·놓음).
  - GUI: 쥔 동안 그 상자를 손끝 노드 아래로 옮겨 그린다. 놓으면 놓은 자리(통이면 통 안 바닥)에 두고 수동 물체 목록에서는 지금처럼 뺀다. 놓인 상자는 [작업 공간 비우기]까지 남긴다.
- 영역: 팔(작음), GUI(`scene3d.py`, `backend.py`).

### F10 학습 화면
- 지금 기구학 엔진에서는 카메라 칸이 "MuJoCo 시뮬레이션에서만 보입니다"뿐이고, 정책 실행 페이지도 비어 보인다. 카메라는 MuJoCo 렌더러가 있어야 하고, 엔진은 앱을 다시 시작해야 바뀐다(`--sim-engine mujoco`).
- 추천:
  1. 기구학 엔진에서는 카메라 칸 자리에 "MuJoCo 엔진으로 다시 시작" 안내(명령 한 줄 복사, MuJoCo 설치 여부)를 둔다. 초음파·3D 칸은 지금처럼 보인다. 정책 실행 페이지에는 체크포인트·씨앗 범위·최근 결과 표(비교 실험 (나) 요약)를 보인다.
  2. 2차에서 ③의 [일시 정지]만 당긴다(작다). ② 수집 화면은 2차로 둔다. 결정 0072-2로 ACT 새 수집을 하지 않기 때문이다.
- 영역: GUI(`pages/views.py`, `pages/policy.py`). 설계는 `gui-spec.md` 12.10의 범위 줄만 고친다.

### F8 캘리브레이션 그리퍼별
- 지금 캘리브레이션은 팔마다 파일 하나(`config/calibration/<id>.json`, 서보 1~6)다. 그리퍼 서보(6)의 범위·영점은 그리퍼마다 다르다.
- 추천 방식(arm-software-spec 7.1에 적는다):
  - 팔 파일에 `calibration_id_by_gripper: {single_jaw: so101_follower_01, parallel: so101_follower_01_parallel}`를 둔다. 없으면 지금처럼 `calibration_id` 하나다.
  - 지금 그리퍼로 고른 id가 LeRobot 캐시 이름, `doctor` 대조, 잠금 해시(`calibration_checked`, id별)에 그대로 쓰인다.
  - 기존 파일은 단동식 것으로 그대로 둔다. 병렬 파일은 기존 파일의 서보 1~5를 복사하고 서보 6만 병렬로 잰 값으로 시작한다(runbook 2-10 "캘리브레이션 그리퍼 범위 다시").
  - 관절 1~5를 다시 재서 저장하면 두 파일 모두 고친다.
  - 그리퍼를 바꾸면 서보 EEPROM의 그리퍼 값이 고른 파일과 달라 움직이는 명령이 잠긴다. `calibrate --save`로 그 그리퍼 파일을 쓰면 풀린다. 이것은 지금 잠금 규칙 그대로다.
  - GUI: 캘리브레이션 마법사 위에 지금 그리퍼와 그 파일 이름을 보이고, 그리퍼 고르기(장치 › 팔, 다시 시작 필요)로 간다.
- 영역: 팔(`core/config.py`, `arm/autocal`, `doctor`), GUI(마법사 표시). 파일·잠금까지는 실물 없이 시험한다. 실물 EEPROM 쓰기는 실물이 올 때 사람이 한다.

### F2·F7 작업 공간 인식을 실제처럼, 초음파 화면
- 설계 초안: `ultrasonic-spec.md` 8.9(소스 고르기, 이벤트 셋, `pace` 고리, 레이더 머리), `gui-spec.md` 12.11(작업 공간 흐름, 3D 겹, 설명 모드·빠른 모드, 초음파 화면 단계 보기).
- 요점:
  - GUI가 인식 소스를 "수동 / 초음파(가상) / 초음파(실물)"로 고른다. 초음파(가상)은 CLI `run --sim --source ultrasonic`과 같은 `make_ultrasonic_source(sim=True, boxes=수동 물체)`다. 수동 물체 목록은 "가상 작업대에 놓인 정답"이 되고, 레이더와 팔 확인이 실제 코드로 그 물체를 찾는다.
