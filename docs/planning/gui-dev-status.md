## G10 세부 (`measurements.md` 실물 시험 순서 2·3번)
세 세션의 실물 시험 순서는 `measurements.md`에 모았다. 실제 팔 없이 할 GUI 일은 끝냈다. 아래만 사용자와 함께 한다. 시작 전에 팔 세션에 "COM3 사용 시작"을 알리고, 다른 브라우저의 Studio 탭을 닫고, 속도 30% 이하, 클램프 고정, 사람은 전원 스위치 옆.
1. 앱 시작: `--sim` 없이 켜고 장치 > 팔 점검 카드의 서보 응답·전압·온도가 "앱을 시작할 때 읽은 값"으로 보이는지 본다. 이 경로는 가짜로만 시험했다.
2. 포트 빠짐 네 경우(홈 정지, 편 자세 정지, 느린 이동, 조그): 0.6초 안에 버스 오류와 버튼 꺼짐, 다시 꽂아도 [다시 연결] 전에는 안 움직임, 재연결 뒤 알림의 토크 상태. `tests/gui/test_port_pull.py`가 가짜 드라이버로 같은 순서를 돌린다. 실제 USB의 예외 종류와 걸리는 시간은 다를 수 있다.
3. 뽑힌 상태에서 화면 E-STOP을 누르고 정지 해제가 풀어 주지 않는지 본다.
4. 토크 풀림 재확인: 0° 자세에서 사람이 받친 채 재연결, status의 토크 값으로 판단.
5. 새 기록 흐름, linkwatch(팔 페이지 버튼. 연결을 끊고 포트를 연 뒤 [진단 중단]으로 끝내면 다시 연결, 토크 유지).
6. 사람이 봐 줄 것: 3D 손잡이 끌기, 3D 로딩 시간, 프로젝터 대비.
7. G10이 끝나면 #41(REQ-017) 합치기, `--verify-zero`, 0° 카드가 "확인됨"으로 바뀌는지 확인.

## G1에서 정해 둔 것
- 사이드바는 1080p에서 스크롤 없이 다 보이고, 720p에서는 스크롤한다. 메뉴 높이 44px을 지키기 위해서다.
- 테스트는 pytest-asyncio를 더하지 않고 `asyncio.run`과 `user_simulation`으로 돈다. `pyproject.toml`의 pytest 설정은 팔 세션 영역이다.

## G2에서 정해 둔 것
- 비어 있는 칸: 센서(G6), 닿는지·오차(G4). 나머지 상태줄 값은 살아 있다.
- 조작권: 처음 연 브라우저가 가진다. 연결이 끊기면 `stop()` 후 비워 두고, 보기 전용 브라우저는 "조작권 받기"를 눌러야 가져간다. 자동으로 넘기면 조작 노트북을 새로고침하는 사이 프로젝터 탭이 조작권을 가져갈 수 있어서다.
- E-STOP은 보기 전용 브라우저도 누를 수 있다. 설계서의 "버튼이 꺼진 보기 전용"에서 E-STOP만 뺐다.
- 아직 팔을 움직이는 버튼이 없어, 조작권이 실제로 막는 버튼은 G4부터 생긴다.

## G9에서 정해 둔 것
- `Backend`는 `sim`과 `real` 두 `ArmService`를 갖는다. `arm`은 `real`이 있으면 `real`이고, 상태줄과 3D의 실제 팔이 읽는다. 계산 자세 팔은 미리보기가 없을 때 시뮬레이션 쪽 자세를 따른다.
- 실제 팔로 가는 명령은 부를 때마다 감시 프로세스가 살아 있는지 확인한다. 없으면 이유를 돌려주고 움직이지 않는다.
- 시뮬레이션 먼저: 시뮬레이션이 끝나면 확인 창이 뜨고, 눌러야 실제 팔이 움직인다. 누르는 조그는 시뮬레이션 팔만 움직인다. 간격 이동은 확인 대상이다.
- 자동 작업은 실제 팔이 있으면 "실제만"에서만 시작한다. 설계서가 다른 방식을 나중으로 미뤘다.
- 정지, E-STOP, 정지 해제, 속도, 안전 설정은 두 팔에 같이 적용한다. 파라미터는 설정 객체를 같이 쓴다.
- `main()`은 아직 `--sim`만 받는다. 실제 팔을 만드는 코드와 `Studio(dry_run=False)` 동작은 G10에서 함께 확인한다.

## G8에서 정해 둔 것
- linkwatch는 포트를 직접 열어 시뮬레이션에서는 버튼을 끈다. 실제 팔에서는 연결을 끊고(토크 유지) 돌린 뒤 다시 연결한다. 그동안 움직이는 버튼은 잠긴다. 포트는 보드 시리얼로 고른 것을 넘긴다.
- 전압과 온도는 축을 나누지 않고 그래프 두 개로 그린다. 3D 다시 보기는 설계서대로 자리만 있다.
- 로그는 이번 실행의 `events.jsonl`과 파이썬 경고·오류를 합친다. 진단은 실행 기록 폴더에 결과를 쓰므로 기록을 끈 `Backend`에서는 powertest가 실패한다(앱은 항상 기록을 켠다).
- `Backend.estop`은 `Studio.stop`과 `ArmService.estop`을 따로 부른다. `Studio.estop`은 실행 기록에 남기지 않는다.

## G7에서 정해 둔 것
- 설계서는 G7 파라미터를 "읽기, 속도만 바로 적용"으로 잡았지만 REQ-004가 이미 있어 값 전체를 적용한다.
- 작업대 배치는 끌기 대신 "고르고 클릭"이다. 저장은 `config/workspace.yaml`의 값만 바꾸고 주석을 지킨다. 저장한 값은 다시 시작해야 적용된다. 센서 위치는 3단계에서 넣는다.
- 파라미터의 "실행 방식" 카드는 G9에서 채운다.
- 3D 칸이 안전 페이지에도 있다. 허용 상자를 보여 주려면 필요하다. 패널이 숨겨진 상태에서는 3D가 뜨는 데 10초 넘게 걸리기도 했다. 화면을 보이게 두고 다시 재야 한다.

## G6에서 정해 둔 것
- 시뮬레이션에는 잡히는 물체가 없어 `Studio(dry_run=True)`로 만든다. 접촉 없음을 성공으로 본다. 실제 팔을 붙일 때(G9·G10) 꺼야 한다.
- 작업 실행 중에는 직접 조작과 교시 재생을 막는다. 물체 추가는 실행 중에도 되고 다음 스캔부터 반영된다.
- 조작하던 브라우저의 연결이 끊기면 작업도 멈춘다.
- `Backend.close`는 팔을 먼저 세운다. 동작 중에 제어 루프만 끄면 기다리던 스레드가 풀리지 않아 앱을 꺼도 프로세스가 끝나지 않았다.
- 일시정지는 REQ-013의 `Studio.pause/resume`을 쓴다. 단계별 모드 정지와 작업 스레드 예외(FAULT)도 팔 쪽에서 고쳐졌다.
- `start_task`는 팔이 idle일 때만 시작한다. 시작하자마자 FAULT로 끝나는 대신 이유를 바로 보여 주기 위해서다.
- 물체 3개의 기본 좌표(`manual_objects.yaml`)는 서로 겹쳐 보인다. 실제 물체 자리를 재면 고칠 값이라 그대로 뒀다.

## G2b에서 정해 둔 것
- REQ-011이 `main`에 들어와 임시 분기를 지웠다. 감시 칸의 `없음`은 이제 `Backend`를 감시 없이 만든 테스트에서만 나온다.
- 설계서는 "실제 팔이 연결되면" `/arm`을 보낸다고 하지만, G2b 완료 기준이 시뮬레이션 기록이라 `--sim`에서도 보낸다. 감시 프로세스가 `--sim`이면 기록만 한다.
- `/arm`은 조작권을 가진 브라우저가 처음 생긴 뒤에 보낸다. 그 전에는 브라우저 heartbeat가 없어 곧바로 끊김으로 보이기 때문이다. **G10 확인 사항:** 실제 팔에서 조작 브라우저를 닫으면 감시가 작동해 `작동함`으로 남고, 다음 조작자가 정지 해제해야 다시 움직인다.
- 브라우저 heartbeat는 Web Worker에서 보낸다. 숨겨진 탭의 `setInterval`은 브라우저가 늦춘다. 탭을 숨긴 채 오래 두는 경우는 시험하지 않았다(G10에서 확인).
- GUI가 강제로 꺼지면 감시 프로세스가 남을 수 있다. 시작할 때 이미 떠 있으면 그것을 쓴다(Windows에서는 같은 포트를 두 번 열 수 있어 요청이 아무 쪽으로나 간다). 남은 프로세스의 `sim` 값이 이번 실행과 다르면 `꺼짐`으로 치고 실제 팔을 막는다.
- `Backend.resume()`은 만들었지만 "정지 해제" 버튼은 G4에서 붙인다. 그 전까지 E-STOP을 누르면 앱을 다시 켜야 한다.
