**U15(병렬 손 미끄러짐 기준·조임 힘)를 언제 무엇으로 정하나**(기획 제안)
- 정하는 때: 로보나인 실물이 와서 runbook 2-10을 한 날. 그날 재는 것은 닫는 시간(스트로크 84mm), 58mm 상자를 쥔 그리퍼 부하 %·전류, 조임 토크 한계 300·200에서 상자를 손으로 당겨 빠지는지다.
- 그 값으로: MuJoCo 힘 한계를 "최대 조임 120N × 토크 한계 비율"(36N·24N)과 견줘 정하고, 미끄러짐 기준은 그 힘에서 `carry58`의 분포를 보고 정한다.
- 그 전에(sim 먼저): 13.10.1이 되면 `pick_grid`를 힘 한계 10N·24N·36N 셋으로 돌려 성공률과 미끄러짐이 힘에 얼마나 민감한지 표로 낸다. 민감하지 않으면 U15는 급하지 않고, 민감하면 2-10의 조임 실측이 M5 표의 전제가 된다.
- 실물이 12/4까지 안 오면: 잠정 4.0mm·10N을 유지하고, 시험장 표에 "조임 힘 잠정"을 적는다.
- **민감도 표 결과(2026-11-18, `measurements.md` "M5 집기 시험장 고정 묶음")**: 10·24·36·120N에서 `placed_ok` 183~185/225로 성공률은 힘과 거의 상관없다. 36·120N의 거짓 성공 3건은 다른 힘에서 재현되지 않고 `realtime_lag`가 56~96건이라 힘 탓인지 가르지 못한다(시계 주입 2차 뒤). 그래서 U15는 위 계획대로 2-10 날 정하고 그때까지 잠정 4.0mm·10N이다.

## 4. 설치 (2026-11-16 사용자 승인, 결정 0066)
| 무엇 | 어디에 | 조건·이유 |
|---|---|---|
| `lerobot[dataset]`(datasets 등) | 앱 환경 `so101` | 데이터셋 기록에 필요하다. 먼저 `pip install --dry-run`으로 numpy 2.2.6(conda 설치본)이 바뀌지 않는지 보고, 바뀌면 빠진 패키지만 `--no-deps`로 넣는다(MuJoCo C24와 같은 방식) |
| CUDA torch(RTX 5070 Ti는 CUDA 12.8 이상 빌드)와 학습용 lerobot | **새 conda 환경 `so101-train`** | 앱 환경의 numpy·torch를 건드리지 않는다. 학습은 명령줄로 따로 돌고, 앱은 지금의 CPU torch로 정책을 실행한다(ACT는 한 번 추론으로 여러 스텝을 내므로 CPU로 충분한지 L4에서 재고, 모자라면 그때 앱 환경의 torch를 바꾸는 승인을 다시 받는다) |
| `so101-nexus-mujoco` 0.3.12 | `so101-train` | 강화학습 데모용. 베타라 버전을 `==`로 고정한다. `teleop` extra는 쓰지 않는다 |
- 버전은 `environment.yml`(앱)과 새 `environment-train.yml`에 `==`로 고정한다(U12와 같은 규칙).

## 5. 사용자에게 물은 것 (2026-11-16 모두 제안대로 승인, 결정 0066)
1. **결정 0062의 "강화학습은 12/4 뒤"를 바꾸는가.** 제안: "so101-nexus 환경에서의 짧은 학습 데모(L5)는 12/4 전에 한다. 우리 장면·`ArmService` 위의 강화학습(시험장 실행기 B, 실물 이어 배우기)은 그대로 12/4 뒤다." 승인하면 새 결정 기록을 쓰고 0062의 상태 줄에 표시한다.
2. **설치 4절**(앱 환경에 `lerobot[dataset]`, 새 환경 `so101-train`에 CUDA torch·so101-nexus)을 승인하는가.
3. **학습한 정책의 실물 실행을 12/4 전 범위에 넣는가.** 추천: 넣지 않는다(시뮬레이션까지). 넣으려면 USB 카메라 두 대 구매와 손목 거치대, 실물 시연 수집 시간이 필요하고 필수 경로(I1)와 같은 주에 겹친다.
4. **VLA**(영상-언어-행동 모델)는 12/4 전 범위에서 뺀다고 봐도 되는가. ACT와 같은 데이터로 나중에 학습할 수 있게 형식만 맞춘다(16GB GPU로 미세 조정은 되지만 시간이 든다).
5. 밀릴 때 자르는 순서(3절: L5 → 게임패드 → 키보드 수집)에 동의하는가.
