# 초음파 인식 설계서 (레이더 + 팔 확인)

상태: 초안 · 2026-11-05 (3.2절 스캔 서보 기종만 사용자 승인 대기)

근거 결정: `decisions/0034`(레이더 + 팔 확인), `0004`(인식 공통 출력), `0006`(ESP32 1개 + HC-SR04 2개), `0013`(작업대 좌표계, 높이는 작업대 면 기준), `0015`(안전 설정), `0026`(E-STOP). 비교 근거는 기획 세션의 가상 센서 시뮬레이션이다(조사 원문은 커밋하지 않는다). 숫자는 실측 전 값이라 10절 B1·B2 실측 뒤 다시 계산한다.

## 1. 목표와 합격 기준
작업대 위 물체 2~3개의 위치와 방향을 초음파만으로 구해 `DetectedObject`(x, y, 각도, 폭, 길이, 신뢰도)로 넘긴다. 집기·GUI·비교 실험은 지금 형식 그대로 쓴다.

| 항목 | 가상 센서 값 (비관~낙관) | 실물 합격 기준 |
|---|---|---|
| 레이더 후보 위치 | 오차 중앙 20~25mm, 90% 약 36mm | 물체 1개 9자리에서 95%가 90mm 안 (확인 경로가 찾을 수 있는 범위) |
| 팔 확인 위치 | 오차 중앙 약 2mm, 90% 3~7mm | 10mm 이하 |
| 팔 확인 방향 | 0/45/90/135° 중 83~100% | 90% 이상 |
| 3개 끝까지 (정확 모드) | 성공 78~93%, 인식 약 26초 | 10회 평균 2개 이상 성공, 인식 30초 이하 |
| 3개 끝까지 (빠른 모드) | 성공 77~88%, 인식 약 17초 | 10회 평균 2개 이상 성공, 인식 20초 이하 |

"성공"은 위치 오차 15mm 이내이면서 방향이 맞은 물체 수다(정사각형 물체는 위치만). "인식 시간"은 레이더와 팔 확인 시간의 합이고, 팔이 집고 놓는 시간은 뺀다.

## 2. 전체 흐름
```
 IDLE ─▶ PREPARE ─▶ SCAN ─▶ DECIDE ─후보 있음─▶ CHECK ─확정─▶ PICK ─▶ PLACE ─┐
           (park)   (레이더)    │                  │                        │
                                │                  └─확인 실패─▶ DECIDE      │
                                └─후보 없음─▶ DONE                          │
                     SCAN ◀──── (놓는 동안 레이더가 미리 돌려 둔 결과) ◀──────┘
```
- `SCAN`: 레이더가 후보 목록을 낸다. 후보는 `angle_deg=None`, `confidence` 0.3 이하인 `DetectedObject`다.
- `DECIDE`: 기존 규칙(도달 범위 안, 팔에서 가까운 순)으로 후보 하나를 고른다.
- `CHECK`(새 상태): 팔이 후보 위를 지나가며 손목 센서로 재서 중심·방향·크기를 확정한다(6절). 물체가 없으면 그 후보를 지우고 `DECIDE`로 돌아간다.
- `PICK`·`PLACE`: 그대로. `PLACE` 동안 레이더가 다음 후보를 미리 찾아 둔다(4절 T5). 그래서 두 번째 물체부터는 `SCAN`이 기다리지 않는다.
- 다른 인식 방식(`ManualSource`, 카메라)은 `CHECK`를 건너뛴다. 인식 방식이 확인 기능을 가졌는지로 정한다(8.2절).

시간 흐름 예 (빠른 모드, 물체 3개):

| 시각(초) | 레이더 | 팔 |
|---|---|---|
| 0~1.4 | 한 방향 회전, 후보 발견 | 대기 |
| 1.4~ | 돌아오는 회전 계속(팔 자리는 지움) | 후보로 출발, 가는 길이 첫 확인선 |
| ~7 | 멈춤(팔 센서 우선) | 확인 끝 → 집기 → 놓기 |
| 놓는 동안 | 4바퀴 돌려 합침 | 배출 구역 |
| 다음 | 결과 준비됨 | 다음 후보로 바로 출발 |

## 5. 레이더 처리 (`radar.py`)
1. **기준값(C1)**: 빈 작업대에서 3바퀴(정방향·역방향·정방향)를 돌려 각도별 중앙값을 저장한다. 바퀴 사이 차이가 20mm를 넘는 각도는 "불안정"으로 표시하고 후보에서 뺀다. 저장: `runs/<시각>/scans/baseline.json`, 최근 값은 `config/ultrasonic_baseline.json`(git 제외).
2. **바퀴 합치기**: 각도별로 그 판단에 쓸 바퀴 값(정확·빠른 모드 모두 처음엔 1~2바퀴, 놓는 동안엔 4바퀴)의 중앙값. 응답 없음은 빼고 센다.
3. **후보**: 기준값보다 30mm(`dip_mm`) 이상 가까운 각도가 2개 이상 이어지면 호 하나. 거리가 25mm 넘게 바뀌면 다른 호로 자른다. 붙어 있는 호(각도 이웃, 대표점 사이 110mm 이하)는 한 물체로 합친다. 대표점은 호들의 (각도 중앙, 거리 중앙값) 평균이고, 후보 위치 = 대표점 + 센서 방향으로 15mm.
4. **팔 지우기**: 그 측정 시각의 팔 관절값으로 링크 점(어깨, 팔꿈치, 손목, 손끝)의 작업대 xy를 구한다. 그 점의 방위 ±(빔 반각 + 5°) 안이면서 거리 차가 60mm 안인 측정은 버린다.
5. **도달 범위**: 후보가 `workspace.yaml`의 `reach_mm` 밖이면 표시만 하고 고르지 않는다.
6. **출력**: `ScanResult.objects`에 후보(`angle_deg=None`, 폭·길이 0, `confidence` 0.1~0.3), `raw`에 각도별 바퀴 값·기준값·호·지운 각도.

## 6. 팔 확인 처리 (`check.py`)
손끝 높이는 3.3절 확인 높이로 고정, 손끝은 수직 아래, 손목 회전은 지금 그대로 둔다. 센서 값 `h = 센서 높이 − 거리`가 15mm 넘으면 "물체 위"다. 측정은 6mm마다 한 번(30Hz에서 팔 180mm/s).

| 단계 | 경로 | 얻는 것 |
|---|---|---|
| L1 | 후보를 지나는 길이 180mm 직선. 정확 모드는 작업대 x축 방향, 빠른 모드는 팔 원점에서 후보로 가는 방향(접근 경로 겸용, T8) | 그 방향 중심 |
| L2 | L1 중심을 지나는 수직 직선 180mm | 다른 방향 중심 → 1차 중심 |
| R | 1차 중심 둘레 반지름 45mm 원, 36점 | 물체가 걸리는 방향들 → 긴 축 각도 φ(두 배 각도 평균), 강도 R |
| L3 | 중심을 지나는 φ 방향 직선 180mm | 긴 축 방향 중심과 길이 |
| L4 | 중심을 지나는 φ+90° 직선 180mm | 짧은 축 중심과 폭 → 최종 중심 |

- 각 직선은 후보 중심(0)을 품거나 가장 가까운 메아리 구간을 고른다. 중간의 응답 없음 1칸은 이어 본다. 빠른 모드는 중심을 지난 구간이 끝나고 3칸 비면 멈춘다(T9).
- **방향**: R > 0.3이면 `angle_deg = φ`(0~180, 연속값). 비교 실험에서는 가까운 0/45/90/135°로 묶는다. R ≤ 0.3이면 정사각형·원형으로 보고 `angle_deg=None`, 집기는 기본 각도로 한다.
- **크기**: L3·L4 구간 길이 − 2 × 빔 반경. 빔 반경 = (센서 높이 − 물체 높이) × tan(빔 반각), 빔 반각은 B1 실측값(그 전에는 7.5°).
- **물체 높이**: 구간 안 `h`의 중앙값. `raw`에 남긴다(집는 높이 참고용).
- **신뢰도**: 0.5 + 0.5 × min(R, 1), 구간이 끊겼거나 L3·L4 중심 차이가 10mm를 넘으면 0.2를 뺀다.
- **실패**: L1·L2 모두 메아리가 없으면 후보 둘레 100×100mm를 20mm 격자로 한 번 훑는다. 그래도 없으면 후보를 지우고 `DECIDE`로 돌아간다(레이더 오검출). 같은 자리가 두 번 실패하면 그 사이클에서 다시 고르지 않는다.
- **안전**: 모든 이동은 기존 안전 검사(관절 한계, 작업 영역, 바닥, 결정 0015·0031)를 거친다. 확인 높이가 물체 높이 + 15mm보다 낮아지는 설정은 거부한다. E-STOP·정지는 그대로 동작하고, 확인 중 정지면 ESP32에 `stop`을 보낸다.

## 7. ESP32 ↔ PC 통신 규약 (`system-architecture.md` 6절 대체)
- USB 시리얼 921600bps(보드가 안 되면 115200), 한 줄에 JSON 하나. 측정 줄은 짧은 키로 40바이트 안팎.
- ESP32는 측정마다 자기 시계(µs)를 붙인다. PC는 연결할 때와 10초마다 `sync`로 시계 차이를 구해 PC 단조 시계로 바꾼다(왕복 시간의 절반을 빼는 방식). 목표 오차 2ms 이하(팔 180mm/s에서 0.4mm).
- 측정 간격: 어느 센서든 앞 측정과 33ms(`ping_gap_ms`) 이상 띄운다. 두 센서가 다 켜져 있으면 팔 센서가 우선이고, 팔 센서가 측정하는 동안 레이더는 멈춘다.

| 방향 | 메시지 | 뜻 |
|---|---|---|
| PC → | `{"cmd":"hello"}` | 펌웨어 버전, 센서·서보 종류 묻기 |
| PC → | `{"cmd":"sync","pc":<ns>}` | 시계 맞추기 |
| PC → | `{"cmd":"sweep","from":10,"to":170,"step":4,"bounce":true,"sweeps":N,"max_mm":600}` | 레이더 회전. N=0이면 `stop`까지 계속 |
| PC → | `{"cmd":"stream","hz":30,"max_mm":300}` | 팔 센서 연속 측정 시작 |
| PC → | `{"cmd":"stop"}` | 회전·연속 측정 멈춤. 서보는 그 각도 유지 |
| PC → | `{"cmd":"servo","deg":90}` | 서보 각도(대기 자세) |
| PC → | `{"cmd":"once","k":"r"\|"a","n":5}` | 한 자리에서 n회(실측용) |
| ← ESP32 | `{"t":"hello","fw":"0.1","servo":"pwm","k":["r","a"]}` | |
| ← ESP32 | `{"t":"sync","pc":<ns>,"us":<µs>}` | |
| ← ESP32 | `{"t":"r","a":86,"d":312,"us":<µs>}` | 레이더 측정. a = 명령 각도(°), d = mm, 응답 없음은 `null` |
| ← ESP32 | `{"t":"a","d":104,"us":<µs>}` | 팔 센서 측정 |
| ← ESP32 | `{"t":"end","dir":1,"us":<µs>}` | 한 방향 회전 끝 (dir 1 = 증가, −1 = 감소) |
| ← ESP32 | `{"t":"err","msg":"..."}` | 오류 |

- 연결이 1초 넘게 끊기면 `UltrasonicSource`는 오류를 내고 작업 실행은 `FAULT`로 간다(팔 통신 끊김과 같은 처리, 결정 0031). 센서 응답 없음(`null`)은 오류가 아니다.

### 8.2 인터페이스 (`system-architecture.md` 4·5절에 추가)
```python
@dataclass
class PathSegment:                 # 작업대 좌표, 손끝은 수직 아래
    points_mm: list[tuple[float, float]]
    tool_z_mm: float
    speed_mm_s: float

@dataclass
class PoseSample:                  # 팔 50Hz 루프의 실제 관절값으로 계산
    t_ns: int                      # PC 단조 시계
    sensor_mm: tuple[float, float, float]   # 팔 센서 위치 (작업대 좌표)

class CheckProbe(Protocol):
    def next_segment(self) -> PathSegment | None: ...
    def feed(self, poses: list[PoseSample]) -> None: ...
    def result(self) -> DetectedObject | None: ...   # None = 물체 없음

class CheckableSource(PerceptionSource, Protocol):
    def start_check(self, candidate: DetectedObject) -> CheckProbe: ...
    def prefetch(self, arm_links_fn) -> None: ...    # 놓는 동안 레이더 미리 돌리기 (T5)
```
작업 실행의 `CHECK`:
```python
probe = source.start_check(cand)
while (seg := probe.next_segment()) is not None:
    poses = arm.follow_path(seg.points_mm, seg.tool_z_mm, seg.speed_mm_s)   # REQ-023
    probe.feed(poses)
obj = probe.result()
```
- `probe.feed`는 그 구간 시각 범위의 ESP32 팔 센서 측정을 `PoseSample`과 시각으로 맞춰(선형 보간) 점(x, y, h)으로 바꾼다.
- 인식 모듈은 팔 모듈을 import하지 않는다. 팔 링크 위치는 작업 실행이 `arm_links_fn`으로 넘긴다(의존 방향 `system-architecture.md` 2절 유지).
- 이벤트(`Studio.bus`): `us.sweep`(각도별 값), `us.candidates`, `us.check_path`(구간과 점), `us.check_result`. GUI는 이것으로 그린다(REQ-024).

## 11. 정할 것과 열린 질문
- 스캔 서보 기종(3.2절 추천 MG90S) — 사용자 승인 대기. 승인되면 이 문서를 확정으로 바꾼다.
- 시연 기본 모드: 정확(가까운 순서 유지, 약 26초) 또는 빠른(약 17초).
- 초음파 세션을 새로 만들지(추천: Sonnet, 폴더 `../so101-studio-us`, 고칠 곳은 `perception/ultrasonic/`, `firmware/`, `tests/perception/`, `config/ultrasonic.yaml`). 세션 구성은 기획 세션 결정으로 남긴다.
- 확인 높이에서 바깥쪽(반경 240mm) 도달이 안 되면 확인 높이나 센서 브래킷 높이를 바꾼다(U3 결과로).
- 레이더 시야에 팔 받침이 들어오는 영향은 기준값에 포함된다고 보고, R1에서 확인한다.
