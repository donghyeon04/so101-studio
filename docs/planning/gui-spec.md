# GUI 설계서

상태: 확정 · 2026-11-02 (1차: 기본 골자) · 2026-11-07 사용자 사용 후 개정(11절), 결정 0044 구조(12절)

근거 결정: `decisions/0020`(API 동결과 GUI 첫 작업), `0022`(디자인 도구), `0023`(NiceGUI 앱 틀 + Viser 3D, 센서별 화면), `0024`(GUI 세션과 팔 세션 분리, 요청서), `0025`(화면 확인과 디자인 기준), `0026`(E-STOP 감시 프로세스), `0027`(팔 파일과 local.yaml, doctor), `0030`(블랙박스 기록), `0031`(XY 복귀 허용, 포트 빠짐 시험), `0034`·`0038`(초음파 레이더 + 팔 확인, 모드 하나). 팀 검토(2026-11-02): 기본 골자를 먼저 만들고 기능은 나중에 붙일 수 있게 확장성을 둔다. 화면 구성의 모티브는 PIPER Studio(WeGo-Robotics/wego-piper-web)이다.

## 1. 원칙
- 완성형 앱이다. 발표는 이 앱을 그대로 프로젝터에 띄우고 직접 조작하며 한다. 청중 전용 기능은 넣지 않는다.
- GUI는 `ArmService`, `Studio`, `PerceptionSource`만 호출한다. 팔과 센서를 직접 다루지 않는다.
- 센서는 끼워 넣는다. 인식 방식마다 자기 페이지와 작업 공간용 작은 화면을 등록하고, 앱은 등록된 것만 메뉴에 붙인다.
- 모든 페이지에 공통 틀이 있다. 위쪽 상태줄, 왼쪽 사이드바, 오른쪽 아래 E-STOP, 아래쪽 상태줄이다.

## 2. 공통 틀
| 영역 | 내용 |
|---|---|
| 위쪽 상태줄 | 앱 이름, 팔(시뮬레이션/실제), 연결된 센서, 실행 방식, 전압, 최고 온도, 속도, 조작권, 구성 요소 상태(팔 버스, 서보 6개, 감시 프로세스, 센서 보드 각각 OK/WARN/ERROR/STALE, Carbon 규칙. `decisions/0030`) |
| 사이드바 | 5개 그룹(3절). 접을 수 있다 |
| 페이지 머리 | 제목, 상태 배지(대기/실행 중/정지/오류), 오른쪽에 그 페이지의 주요 버튼 |
| E-STOP | 모든 페이지 오른쪽 아래에 빨간 원형 버튼으로 고정. `ArmService.estop()` |
| 아래쪽 상태줄 | 손끝 좌표, 닿는지 여부와 오차, 안전 모드, 토크, 기록 폴더 |
| 조작권 | 처음 접속한 브라우저만 조작할 수 있고, 나머지는 보기 전용이다. 조작하던 브라우저의 연결이 끊기면 `stop()` |

## 4. 화면 요소 규칙
- 3D(Viser): 실제 팔(불투명), 계산 자세(반투명 보라), 손끝 경로(점선), 작업대, 물체, 배출 구역, 허용 상자, 좌표축(작업대/로봇/툴).
- 센서 2D 화면과 3D는 같은 작업대 좌표(mm)를 쓴다. 한쪽에서 고른 물체는 다른 쪽에서도 강조된다.
- 실행 방식(동시 / 시뮬레이션 먼저 하고 확인 / 시뮬레이션만 / 실제만)은 파라미터 페이지에서 고르고 위쪽 상태줄에 늘 보인다.
- 닿지 않는 목표, 안전 검사에 걸린 명령은 움직이지 않고 이유를 아래쪽 상태줄과 알림으로 보여 준다(`preview_tool`, `MotionResult.status`).

## 6. 1차 범위 (기본 골자)
- 만든다: 공통 틀, 13개 페이지의 자리(11절 개정으로 시작 화면 `/start`가 더해져 14개), 시뮬레이션에서 동작하는 직접 조작·교시 재생·작업 공간(수동 입력), 안전, 상태·기록 보기, 3D(실제 팔·계산 자세·작업대·물체), 실행 방식 4가지(직접 조작과 재생).
- 자리만 둔다: 초음파와 ESP32(3단계에서 채움, 초음파는 결정 0034·0038의 레이더 + 팔 확인 방식), 카메라(4단계), 실행 기록의 3D 다시 보기.
- 나중: 어두운 테마, 실험 그룹(기능명세서 F3·F4), 작업 공간 자동 실행의 "시뮬레이션 먼저" 방식, 장치 > 팔의 자동 캘리브레이션 마법사(시작 자세 그림, 진행, 기존 값과 비교표 또는 3회 반복표, 저장 확인, 0° 자세 확인에서 실물과 3D URDF를 나란히 보여 주고 확인 버튼. REQ-016·017과 AC4 실물 시험이 끝난 뒤, `decisions/0028`·`0029`).

## 7. 폴더 구조
```
src/so101_studio/gui/
  __main__.py        python -m so101_studio.gui [--sim] [--port 8080] [--viser-port 8081]
  app.py             NiceGUI 앱: 공통 틀(위쪽 상태줄, 사이드바, 아래쪽 상태줄, E-STOP), 페이지 등록
  backend.py         ArmService·Studio를 감싸는 유일한 창구. 실행 방식, 조작권, REQ 임시 우회
  state.py           화면이 읽는 상태(최신 ArmStatus, 물체 목록, 작업 단계, 최근 이벤트)
  scene3d.py         Viser 서버, URDF 팔 두 개, 작업대·물체·경로·허용 상자, 클릭과 끌기 손잡이
  theme.py           5절의 색과 크기
  watchdog_link.py   감시 프로세스 띄우기, 서버 heartbeat, 브라우저 heartbeat 스크립트, 감시 상태 읽기 (0026)
  pages/             workspace.py, manual.py, teach.py, input.py, arm.py, esp32.py,
                     params.py, safety.py, table.py, runs.py, logs.py
  sensors/           __init__.py(센서 화면 등록부), manual_view.py, ultrasonic_view.py(3단계), camera_view.py(4단계)
tests/gui/           backend와 state 단위 테스트, NiceGUI 테스트 도구(user fixture)로 페이지 이동
```
- 페이지는 `backend`와 `state`만 쓴다. `ArmService`를 직접 부르지 않는다.
- 센서 화면 등록부: `register(name, title, page_fn, mini_view_fn)`. 인식 그룹 메뉴와 작업 공간 오른쪽 칸은 등록된 것으로 그린다. 1차에는 수동 입력만 등록하고, 초음파와 카메라는 "추가 예정" 자리를 보여 준다. 초음파는 REQ-024에서 등록한다.

## 8. 실행 구조
| 부분 | 방식 |
|---|---|
| NiceGUI | 메인 스레드의 이벤트 루프. 팔을 움직이는 호출은 `run.io_bound`(스레드)로 보내 화면이 멈추지 않게 한다 |
| 상태 | `ArmService.status_stream`(10Hz)이 `state`에 최신 값을 쓴다. 화면은 `ui.timer`(10Hz)로 읽고, 3D는 콜백에서 바로 갱신한다 |
| Viser | 같은 프로세스에서 다른 포트로 띄우고, 페이지 안 3D 칸에 `iframe`으로 넣는다. 작업대 클릭은 Viser 포인터 이벤트의 광선과 작업대 면의 교점으로 좌표를 구한다 |
| 실행 방식 | `backend`가 `ArmService`를 두 개 가진다: 실제 장치용과 `SimDriver`용. 시뮬레이션만 / 실제만 = 하나만 호출, 동시 = 둘을 같이 호출, 시뮬레이션 먼저 = 시뮬레이션에서 끝까지 보여 준 뒤 확인 창을 거쳐 실제를 호출. `--sim`으로 띄우면 시뮬레이션 하나만 있다. 계산 자세 팔은 시뮬레이션 쪽 자세를 보여 준다 |
| 조작권 | 처음 연결된 브라우저가 조작권을 가진다. 다른 브라우저는 버튼이 꺼진 보기 전용이다. 조작권을 가진 브라우저의 연결이 끊기면 `stop()`(토크는 유지) |
| E-STOP | 모든 페이지에서 `backend.estop()` → 두 `ArmService`와 작업을 함께 멈춘다 |
| 감시 프로세스 | `decisions/0026`. GUI가 시작할 때 `python -m so101_studio.watchdog`을 함께 띄운다(`gui/watchdog_link.py`). 조작권을 가진 브라우저는 페이지에 넣은 스크립트로 감시 프로세스에 직접 heartbeat를 보내고(0.2초마다), GUI 서버는 이벤트 루프에서 따로 보낸다. 실제 팔이 연결된 동안 둘 중 하나가 1초 넘게 끊기면 감시 프로세스가 팔 프로세스에 정지를 보내고, 0.3초 안에 응답이 없으면 그 프로세스(`ArmService`가 들어 있는 GUI 프로세스)를 끝낸다. 감시 프로세스가 없거나 응답하지 않으면 GUI는 실제 팔 명령을 막고 위쪽 상태줄에 "감시 꺼짐"을 띄운다. 감시 프로세스의 단축키 E-STOP은 화면과 상관없이 동작한다 |

### A. 첫 화면과 상단 막대
- **1 시작 화면** `/start`: 앱을 켜면 처음 나온다. 사이드바 맨 위 "시작"과 상단 앱 이름 "SO-101 Studio"를 누르면 언제든 돌아온다. 위에서부터:
  1. 모드 카드: "시뮬레이션" 또는 "실물" 큰 글자, 팔 연결 상태(실물 팔 연결됨 / 포트에 보드 있음·앱은 시뮬레이션 / 팔 없음 / 잠김과 이유). 보드가 꽂혀 있는데 시뮬레이션으로 켰으면 실물로 켜는 방법을 알린다(지금은 `실물 팔 실행.cmd`, 2차부터 3의 버튼).
  2. 처음이면 이 순서로: 직접 조작에서 팔 움직여 보기 → 교시에서 기록 재생 → 작업 공간에서 수동 입력 물체로 자동 실행. 각 항목은 그 페이지로 가는 버튼이다.
  3. 페이지 안내: 그룹별 카드, 페이지마다 한 줄 설명(D11과 같은 문구).
  4. 최근 실행 기록 3개.
- **2 상단 오른쪽 버튼**: 실행 방식 선택(4가지, 지금 팔·파라미터 페이지에 있는 것과 같은 상태), [다시 연결](아이콘, `ArmService` 다시 연결, 실행 중이면 꺼짐), [점검](아이콘, `doctor --json` 결과를 시작 화면 모드 카드와 같은 형식으로 띄움), 그리퍼 속도 막대(지금 파라미터의 그리퍼 속도, 바로 적용)와 그 옆 작은 그래프(최근 10초 그리퍼 위치). 원래 자리의 같은 기능은 그대로 두고 같은 상태를 쓴다.
- **3 시뮬레이션↔실물 전환 (2차)**: 앱 안에서 바꾸지 않고 다시 시작한다. 시작 화면에 [실물로 다시 시작] / [시뮬레이션으로 다시 시작] 버튼을 두고, 누르면 확인 창 → 지금 앱과 감시 프로세스를 닫고 `so101.cmd [--sim] gui`를 새로 띄운다. 실물로 바꿀 때는 보드 연결과 `doctor` 결과를 먼저 보여 준다. 실행 중이면 버튼이 꺼진다.

### B. 직접 조작
- **4 공중 점 고르기 (2차)**: 3D 클릭은 지금처럼 작업대 점을 찍고, 찍은 뒤 그 점 위에 높이 막대(작업대 위 0~300mm, 숫자 입력 겸용)가 나온다. 3D에 점에서 위로 선을 그어 높이를 보여 주고, 미리보기 → 이동은 그대로다. 손잡이 끌기는 지금처럼 둔다.
- **5 조이스틱 (1차)**: 3D 옆 별도 칸에 xy 패드(원형, 중심에서 멀수록 빠름), 높이 막대(위/아래 누르는 동안), yaw 돌리기 버튼 두 개. 누르는 동안만 움직이고 떼면 선다(기존 직교 조그 API, 조그 속도 설정을 따름). 좌표계는 작업대/손끝 중 고른다. 3D 좌표축의 작은 화살표는 뺀다.
- **6 손끝 방향 자유롭게 (2차)**: 좌표 이동과 조이스틱에 pitch·yaw 선택을 넣는다(기본은 지금처럼 아래). pitch는 팔 쪽 IK·안전 검사가 손끝 방향을 받아야 하므로 9와 같은 REQ로 팔 세션에 보낸다.
- **7 집어 옮기기 (1차)**: 직접 조작에 [집기 점] [놓기 점] 두 단계. 3D나 좌표로 집기 점을 찍고 물체 크기·각도(기본: 수동 입력 기본값)를 정한 뒤, 놓기 점(또는 배출 구역)을 찍고 [집어 옮기기] → 미리보기 → 실행. 실행은 `Skills.pick`/`place`를 거친다(REQ-031: 직접 조작에서 부를 공개 함수, 이미 있으면 확인만). 집기 범위 밖 점은 버튼이 꺼지고 이유를 보인다.
- **8 시뮬레이션 먼저 미리보기 (1차)**: "시뮬레이션 먼저" 실행 방식에서, 계산이 끝나면 3D 계산 자세(보라색) 팔이 `preview_path`(REQ-008) 샘플을 실제 속도로 재생하고, 재생이 끝나면 확인 창 [실물에서 실행] / [취소]. 계산 중에는 "계산 중" 표시. 재생 중에도 [취소]가 된다.

### C. 작업 범위
- **9 범위 나누기 (2차)**: `workspace.yaml`의 `reach_mm` 90~250은 그리퍼를 아래로 향한 수직 하강으로 작업대 면에서 IK가 풀리는 반경이다(`measurements.md` T6). 이것을 **집기 범위**로 이름을 바꿔 작업 실행·물체 판정에 그대로 쓰고, 따로 **움직임 범위**(손끝 방향 자유, 높이별 도달)를 둔다. 움직임 범위는 직접 조작·조이스틱·안전 상자 표시에 쓴다. 값은 팔 세션이 `--sim` 기구학으로 하나의 계산으로 낸다(결정 0037). 설정 이름 변경과 계산은 REQ로 팔 세션에 보낸다(6과 같은 REQ). 3D에는 두 범위를 다른 색 테두리로 그린다.
- **10 초음파 접근 호버 도달 띠 (2차, 보류)**: 접근 호버(첫 점 위 40mm)에서는 도달 띠가 반경 약 76~238mm로 좁다. REQ-030(`plan_goto` 여러 시드)이 합쳐진 뒤, 벤치마크에 세 안을 옵션으로 붙여 숫자로 비교하고 기획이 정한다(결정 0037): (가) 호버 높이 낮추기, (나) `check.tool_reach_mm`를 호버 기준으로 줄이기, (다) 닿지 않는 첫 점을 경로 안쪽으로 당기기. 정해지면 `ultrasonic-spec.md` 6절과 1절을 고친다.

### D. 수동 입력·작업대 좌표
- **11 쓰임 보이기와 간편 조작 (1차)**: 모든 페이지 머리 제목 아래에 회색 한 줄 설명을 둔다(시작 화면 페이지 안내와 같은 문구). 수동 입력 = "센서 대신 사람이 물체 위치를 알려 주는 인식 방식입니다. 작업 공간 자동 실행이 이 물체들을 집습니다." 작업대·좌표 = "팔 받침, 배출 구역, 센서가 작업대 어디에 있는지 정합니다." 두 페이지에서 물체나 배치 항목을 고르면 5의 xy 패드와 돌리기 버튼으로 옮길 수 있다(누를 때마다 5mm·5°, 길게 누르면 계속). 저장은 지금처럼 따로 누른다.

## 12. 결정 0044 반영: 구조는 유지하고 고쳐 쓴다 (2026-11-07)
뼈대(왼쪽 메뉴 + 위 상태줄 + 항상 보이는 E-STOP)는 그대로다. 아래를 고치고 더한다. 구현 순서: 메뉴 정리 → 조작 막대·조그 패널 → 자세 목록·프로그램 트리 → 캘리브레이션 마법사 → 운영자 화면 → 장면 부품 편집기 → MuJoCo.

### 12.1 공통 틀에 더하는 것
| 영역 | 내용 |
|---|---|
| 메뉴 | 카메라는 카메라를 달 때까지 숨긴다. 작업 그룹에 "프로그램"을 더한다. 캘리브레이션 마법사는 장치 › 팔 아래. 실험 그룹은 0044대로 카메라 뒤 |
| 아래 조작 막대 | 모든 페이지 아래에 고정: 속도 막대(%), [정지 해제](`resume`), [홈], 조그 패널 열기, 그리고 기존 E-STOP 버튼. 아래쪽 상태줄(손끝 좌표 등)은 이 막대 위 한 줄로 남긴다 |
| 조그 패널 | 어느 페이지에서나 여는 떠 있는 패널: 관절 조그(관절별 −/+ 와 값 입력), 직교 조그(11절 B5 조이스틱과 같은 부품), 그리퍼. 직접 조작 페이지와 같은 상태를 쓴다 |
| 서보 건강 | 상단 구성 요소 상태에 서보 건강 요약(정상/주의/위험). 주의 기준: 온도 50°C, 부하 70%, 전류 3A, 전압 11.5V, 3초 넘게 이어질 때. 장치 › 팔에 서보 6개 시간 그래프 |
| 그리퍼 선택 | 장치 › 팔에 그리퍼 종류(단동식/병렬)를 보이고 바꾼다. 바꾸면 다시 연결이 필요하다고 알린다(결정 0043-1) |
| 장면 부품 | 3D에 `config/scene.yaml` 부품을 그린다. 임시 상자는 반투명으로 구분한다. 편집기는 STEP을 받은 뒤(0044 순서) |
| 오류 알림 | fault는 알림과 상태줄에 원인 문장(결정 0042-5)을 보인다 |

### 12.2 프로그램 (작업 › 프로그램)
- 왼쪽: 자세 즐겨찾기 목록(`config/waypoints.yaml`). [지금 자세 저장], 이름 바꾸기, 3D 미리보기, [그 자세로 이동].
- 가운데: 프로그램 트리(`config/programs/<이름>.yaml`). 단계 블록: 자세로 이동, 직선 이동, 그리퍼 열기/닫기, 집기, 놓기, 기다리기, 반복. 끌어서 순서를 바꾸고, 블록을 고르면 오른쪽에 값.
- 위: [실행] [한 단계] [정지], 실행 방식은 상단 선택을 따른다. 실행 중 지금 블록을 강조한다.

### 12.3 캘리브레이션 마법사 (장치 › 팔 › 캘리브레이션)
`calibrate --auto --measure-only`, `--save`, `--verify-zero`(결정 0028, REQ-016·017)를 단계 화면으로 감싼다. 실제 팔에서만 켜지고, 시뮬레이션에서는 단계 설명만 보인다.

```
┌ 캘리브레이션 ─────────────────────────────── 1 준비 › 2 측정 › 3 비교 › 4 저장 › 5 0° 확인 ┐
│ [단계 그림]                 │ 이 단계에서 할 일 (3~4줄)                                  │
│  1 준비: 시작 자세 그림       │ □ 클램프로 고정  □ 반경 50cm 비움  □ 전원 스위치 옆에 사람  │
│  2 측정: 관절별 진행 막대     │ 전압 ▮▮▮▮ 11.8V (11.0V 미만이면 중단)  최고 온도 34°C (60°C) │
│  3 비교: 관절 표(범위·0° 차이)│ 합격/불합격 배지, 3회 반복이면 3열 + 중앙값                   │
│  4 저장: 확인 창(yes 입력)    │ .bak.json 경로, EEPROM·캐시·config 세 곳에 씀                │
│  5 0° 확인: 실물 사진 자리 ↔ 3D URDF 나란히, [맞음] [다름]                                │
│                                          [이전] [다음] (조건을 다 채워야 켜짐) [중단]   │
└────────────────────────────────────────────────────────────────────────────────┘
```
- 준비 체크 세 개를 모두 눌러야 [다음]이 켜진다. 측정 중에는 [중단]만 있고, 중단하면 컨트롤러가 되돌린다.
- 전압·온도가 기준을 넘으면 측정을 멈추고 이유를 그 자리에 보인다(결정 0043-3: 먼저 전원 경로 점검 안내 링크).
- 저장(4)은 사용자가 `yes`를 입력해야 한다. 0° 확인(5)이 끝나야 잠금이 풀린다(REQ-017).

### 12.4 운영자 화면 (시연용, `/operator`)
프로젝터와 시연 진행자용 단순 화면이다. 설정·진단 버튼은 숨긴다. 읽기 전용 보기는 이 화면을 다른 기기에서 여는 것이다.

```
┌ SO-101 · 시뮬레이션/실물 · 인식: 초음파 ─────────────────── [E-STOP] ┐
│  ┌ 3D (크게) ───────────────────────┐  ┌ 지금 단계 ─────────────┐  │
│  │ 팔·물체·레이더 부채꼴·확인 경로    │  │ ● 스캔 ○ 판단 ○ 확인    │  │
│  │                                    │  │ ○ 집기 ○ 놓기  (크게)   │  │
│  └────────────────────────────────────┘  │ 물체 2/3 · 걸린 시간 41초│  │
│  ┌ 물체 목록 ───────────────────────┐    └─────────────────────────┘  │
│  │ us-1 ✓ 놓음 · us-2 확인 중 · us-3 대기                            │  │
│  └──────────────────────────────────┘                                  │
│  [시작]  [한 단계]  [일시정지]  [정지]        다른 기기에서 보기: http://… │
└───────────────────────────────────────────────────────────────────────┘
```
- 글자는 프로젝터 기준으로 크게(본문 20px 이상), 상태는 색 + 아이콘 + 글자(Carbon).
- 조작권이 없는 브라우저(읽기 전용)는 아래 버튼 줄이 숨겨지고 "보기 전용"이 보인다. E-STOP은 조작권이 있는 화면에만 있다.
- 단계는 작업 실행 상태(`PREPARE`·`SCAN`·`DECIDE`·`CHECK`·`RESCAN`·`PICK`·`PLACE`)를 그대로 보인다(11절 이후 알려진 문제 3, `CHECK`·`RESCAN` 표시).
