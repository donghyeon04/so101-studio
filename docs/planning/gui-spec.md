## 1. 원칙
- 완성형 앱이다. 발표는 이 앱을 그대로 프로젝터에 띄우고 직접 조작하며 한다. 청중 전용 기능은 넣지 않는다.
- GUI는 `ArmService`, `Studio`, `PerceptionSource`만 호출한다. 팔과 센서를 직접 다루지 않는다.
- 센서는 끼워 넣는다. 인식 방식마다 자기 페이지와 작업 공간용 작은 화면을 등록하고, 앱은 등록된 것만 메뉴에 붙인다.
- 모든 페이지에 공통 틀이 있다. 위쪽 상태줄, 왼쪽 사이드바, 오른쪽 아래 E-STOP, 아래쪽 상태줄이다.

## 2. 공통 틀
| 영역 | 내용 |
|---|---|
| 위쪽 상태줄 | 앱 이름, 팔(시뮬레이션/실제), 연결된 센서, 실행 방식, 전압, 최고 온도, 속도, 조작권, 구성 요소 상태(팔 버스, 서보 6개, 감시 프로세스, 센서 보드 각각 OK/WARN/ERROR/STALE, Carbon 규칙. `decisions/0030`) |
| 사이드바 | 5개 그룹(3절). 접을 수 있다 |
| 페이지 머리 | 제목, 상태 배지(대기/실행 중/정지/오류), 오른쪽에 그 페이지의 주요 버튼 |
| E-STOP | 모든 페이지 오른쪽 아래에 빨간 원형 버튼으로 고정. `ArmService.estop()` |
| 아래쪽 상태줄 | 손끝 좌표, 닿는지 여부와 오차, 안전 모드, 토크, 기록 폴더 |
| 조작권 | 처음 접속한 브라우저만 조작할 수 있고, 나머지는 보기 전용이다. 조작하던 브라우저의 연결이 끊기면 `stop()`. 보기 전용도 E-STOP은 누를 수 있다. 원격 브라우저(접속한 쪽 IP가 루프백이 아닌 것)는 조작권을 가질 수 없다(결정 0047·0049, 12.6) |

## 4. 화면 요소 규칙
- 3D(Viser): 실제 팔(불투명), 계산 자세(반투명 보라), 손끝 경로(점선), 작업대, 물체, 배출 구역, 허용 상자, 좌표축(작업대/로봇/툴).
- 센서 2D 화면과 3D는 같은 작업대 좌표(mm)를 쓴다. 한쪽에서 고른 물체는 다른 쪽에서도 강조된다.
- 실행 방식(동시 / 시뮬레이션 먼저 하고 확인 / 시뮬레이션만 / 실제만)은 파라미터 페이지에서 고르고 위쪽 상태줄에 늘 보인다.
- 닿지 않는 목표, 안전 검사에 걸린 명령은 움직이지 않고 이유를 아래쪽 상태줄과 알림으로 보여 준다(`preview_tool`, `MotionResult.status`).

## 6. 1차 범위 (기본 골자)
- 만든다: 공통 틀, 13개 페이지의 자리(11절 개정으로 시작 화면 `/start`가 더해져 14개), 시뮬레이션에서 동작하는 직접 조작·교시 재생·작업 공간(수동 입력), 안전, 상태·기록 보기, 3D(실제 팔·계산 자세·작업대·물체), 실행 방식 4가지(직접 조작과 재생).
- 자리만 둔다: 초음파와 ESP32(3단계에서 채움, 초음파는 결정 0034·0038의 레이더 + 팔 확인 방식), 카메라(4단계), 실행 기록의 3D 다시 보기.
- 나중: 어두운 테마, 실험 그룹(기능명세서 F3·F4), 작업 공간 자동 실행의 "시뮬레이션 먼저" 방식, 장치 > 팔의 자동 캘리브레이션 마법사(시작 자세 그림, 진행, 기존 값과 비교표 또는 3회 반복표, 저장 확인, 0° 자세 확인에서 실물과 3D URDF를 나란히 보여 주고 확인 버튼. `decisions/0028`·`0029`). 마법사는 12.3대로 두 번에 나눈다: 측정·비교(1~3단계)는 지금, 저장·0° 확인(4·5단계)은 REQ-017(#41)과 AC4 실물 시험 뒤.

## 7. 폴더 구조
```
src/so101_studio/gui/
  __main__.py        python -m so101_studio.gui [--sim [--sim-engine kinematic|mujoco] [--sim-viewer]] [--port 8080] [--viser-port 8081] [--share]
  app.py             NiceGUI 앱: 공통 틀(위쪽 상태줄, 사이드바, 아래쪽 상태줄, E-STOP), 페이지 등록
  backend.py         ArmService·Studio를 감싸는 유일한 창구. 실행 방식, 조작권, REQ 임시 우회
  state.py           화면이 읽는 상태(최신 ArmStatus, 물체 목록, 작업 단계, 최근 이벤트)
  scene3d.py         Viser 서버, URDF 팔 두 개, 작업대·물체·경로·허용 상자, 클릭과 끌기 손잡이
  theme.py           5절의 색과 크기
  watchdog_link.py   감시 프로세스 띄우기, 서버 heartbeat, 브라우저 heartbeat 스크립트, 감시 상태 읽기 (0026)
  pages/             workspace.py, manual.py, teach.py, input.py, arm.py, esp32.py,
                     params.py, safety.py, table.py, runs.py, logs.py
  sensors/           __init__.py(센서 화면 등록부), manual_view.py, ultrasonic_view.py(3단계), camera_view.py(4단계)
tests/gui/           backend와 state 단위 테스트, NiceGUI 테스트 도구(user fixture)로 페이지 이동
```
- 페이지는 `backend`와 `state`만 쓴다. `ArmService`를 직접 부르지 않는다.
- 센서 화면 등록부: `register(name, title, page_fn, mini_view_fn)`. 인식 그룹 메뉴와 작업 공간 오른쪽 칸은 등록된 것으로 그린다. 1차에는 수동 입력만 등록하고, 초음파와 카메라는 "추가 예정" 자리를 보여 준다. 초음파는 REQ-024에서 등록한다.

## 8. 실행 구조
| 부분 | 방식 |
|---|---|
| NiceGUI | 메인 스레드의 이벤트 루프. 팔을 움직이는 호출은 `run.io_bound`(스레드)로 보내 화면이 멈추지 않게 한다 |
| 상태 | `ArmService.status_stream`(10Hz)이 `state`에 최신 값을 쓴다. 화면은 `ui.timer`(10Hz)로 읽고, 3D는 콜백에서 바로 갱신한다 |
| Viser | 같은 프로세스에서 다른 포트로 띄우고, 페이지 안 3D 칸에 `iframe`으로 넣는다. 작업대 클릭은 Viser 포인터 이벤트의 광선과 작업대 면의 교점으로 좌표를 구한다 |
| 실행 방식 | `backend`가 `ArmService`를 두 개 가진다: 실제 장치용과 시뮬레이션용(`SimDriver`. `--sim --sim-engine mujoco`면 `MuJoCoDriver`, 12.8). 시뮬레이션만 / 실제만 = 하나만 호출, 동시 = 둘을 같이 호출, 시뮬레이션 먼저 = 시뮬레이션에서 끝까지 보여 준 뒤 확인 창을 거쳐 실제를 호출. `--sim`으로 띄우면 시뮬레이션 하나만 있다. 계산 자세 팔은 시뮬레이션 쪽 자세를 보여 준다 |
| 조작권 | 처음 연결된 **루프백** 브라우저가 조작권을 가진다(원격 판정은 12.6). 다른 브라우저는 버튼이 꺼진 보기 전용이다. 조작권을 가진 브라우저의 연결이 끊기면 `stop()`(토크는 유지). 감시 프로세스(8090·8091)는 `--share`여도 계속 `127.0.0.1`에만 연다. 조작권 브라우저의 heartbeat가 `location.hostname:8090`으로 가므로 조작권은 루프백 브라우저에만 준다 |
| E-STOP | 모든 페이지에서 `backend.estop()` → 두 `ArmService`와 작업을 함께 멈춘다 |
| 감시 프로세스 | `decisions/0026`. GUI가 시작할 때 `python -m so101_studio.watchdog`을 함께 띄운다(`gui/watchdog_link.py`). 조작권을 가진 브라우저는 페이지에 넣은 스크립트로 감시 프로세스에 직접 heartbeat를 보내고(0.2초마다), GUI 서버는 이벤트 루프에서 따로 보낸다. 실제 팔이 연결된 동안 둘 중 하나가 1초 넘게 끊기면 감시 프로세스가 팔 프로세스에 정지를 보내고, 0.3초 안에 응답이 없으면 그 프로세스(`ArmService`가 들어 있는 GUI 프로세스)를 끝낸다. 감시 프로세스가 없거나 응답하지 않으면 GUI는 실제 팔 명령을 막고 위쪽 상태줄에 "감시 꺼짐"을 띄운다. 감시 프로세스의 단축키 E-STOP은 화면과 상관없이 동작한다 |

### A. 첫 화면과 상단 막대
- **1 시작 화면** `/start`: 앱을 켜면 처음 나온다. 사이드바 맨 위 "시작"과 상단 앱 이름 "SO-101 Studio"를 누르면 언제든 돌아온다. 위에서부터:
  1. 모드 카드: "시뮬레이션" 또는 "실물" 큰 글자, 팔 연결 상태(실물 팔 연결됨 / 포트에 보드 있음·앱은 시뮬레이션 / 팔 없음 / 잠김과 이유). 보드가 꽂혀 있는데 시뮬레이션으로 켰으면 실물로 켜는 방법을 알린다(지금은 앱을 닫고 바탕화면 "SO-101 Studio"로 다시 켠다. 실행 파일이 하나(`SO-101 Studio 실행.cmd`)라 팔이 보이면 실물로, 없으면 시뮬레이션으로 켜진다(REQ-095 #489·#490·#492). 2차부터 3의 버튼).
  2. 처음이면 이 순서로: 직접 조작에서 팔 움직여 보기 → 교시에서 기록 재생 → 작업 공간에서 수동 입력 물체로 자동 실행. 각 항목은 그 페이지로 가는 버튼이다.
  3. 페이지 안내: 그룹별 카드, 페이지마다 한 줄 설명(D11과 같은 문구).
  4. 최근 실행 기록 3개.
- **2 상단 오른쪽 버튼**: 실행 방식 선택(4가지, 지금 팔·파라미터 페이지에 있는 것과 같은 상태), [다시 연결](아이콘, `ArmService` 다시 연결, 실행 중이면 꺼짐), [점검](아이콘, `doctor --json` 결과를 시작 화면 모드 카드와 같은 형식으로 띄움), 그리퍼 속도 막대(지금 파라미터의 그리퍼 속도, 바로 적용)와 그 옆 작은 그래프(최근 10초 그리퍼 위치). 원래 자리의 같은 기능은 그대로 두고 같은 상태를 쓴다.
- **3 시뮬레이션↔실물 전환 (2차)**: 앱 안에서 바꾸지 않고 다시 시작한다. 시작 화면에 [실물로 다시 시작] / [시뮬레이션으로 다시 시작] 버튼을 두고, 누르면 확인 창 → 지금 앱과 감시 프로세스를 닫고 `so101.cmd [--sim] gui`를 새로 띄운다. 실물로 바꿀 때는 보드 연결과 `doctor` 결과를 먼저 보여 준다. 실행 중이면 버튼이 꺼진다.

### B. 직접 조작
- **4 공중 점 고르기 (2차)**: 3D 클릭은 지금처럼 작업대 점을 찍고, 찍은 뒤 그 점 위에 높이 막대(작업대 위 0~300mm, 숫자 입력 겸용)가 나온다. 3D에 점에서 위로 선을 그어 높이를 보여 주고, 미리보기 → 이동은 그대로다. 손잡이 끌기는 지금처럼 둔다.
- **5 조이스틱 (1차)**: 3D 옆 별도 칸에 xy 패드(원형, 중심에서 멀수록 빠름), 높이 막대(위/아래 누르는 동안), yaw 돌리기 버튼 두 개. 누르는 동안만 움직이고 떼면 선다(기존 직교 조그 API, 조그 속도 설정을 따름). 좌표계는 작업대/손끝 중 고른다. 3D 좌표축의 작은 화살표는 뺀다.
- **6 손끝 방향 자유롭게 (2차)**: 좌표 이동과 조이스틱에 pitch·yaw 선택을 넣는다(기본은 지금처럼 아래). pitch는 팔 쪽 IK·안전 검사가 손끝 방향을 받아야 하므로 9와 같은 REQ로 팔 세션에 보낸다.
- **7 집어 옮기기 (1차)**: 직접 조작에 [집기 점] [놓기 점] 두 단계. 3D나 좌표로 집기 점을 찍고 물체 크기·각도(기본: 수동 입력 기본값)를 정한 뒤, 놓기 점(또는 배출 구역)을 찍고 [집어 옮기기] → 미리보기 → 실행. 실행은 `Skills.pick`/`place`를 거친다(REQ-031: 직접 조작에서 부를 공개 함수, 이미 있으면 확인만). 집기 범위 밖 점은 버튼이 꺼지고 이유를 보인다.
- **8 시뮬레이션 먼저 미리보기 (1차)**: "시뮬레이션 먼저" 실행 방식에서, 계산이 끝나면 3D 계산 자세(보라색) 팔이 `preview_path`(REQ-008) 샘플을 실제 속도로 재생하고, 재생이 끝나면 확인 창 [실물에서 실행] / [취소]. 계산 중에는 "계산 중" 표시. 재생 중에도 [취소]가 된다.

### C. 작업 범위
- **9 범위 나누기 (2차)**: `workspace.yaml`의 `reach_mm` 90~250은 그리퍼를 아래로 향한 수직 하강으로 작업대 면에서 IK가 풀리는 반경이다(`measurements.md` T6). 이것을 **집기 범위**로 이름을 바꿔 작업 실행·물체 판정에 그대로 쓰고, 따로 **움직임 범위**(손끝 방향 자유, 높이별 도달)를 둔다. 움직임 범위는 직접 조작·조이스틱·안전 상자 표시에 쓴다. 값은 팔 세션이 `--sim` 기구학으로 하나의 계산으로 낸다(결정 0037). 설정 이름 변경과 계산은 REQ로 팔 세션에 보낸다(6과 같은 REQ). 3D에는 두 범위를 다른 색 테두리로 그린다.
- **10 초음파 접근 호버 도달 띠 (2차, 보류)**: 접근 호버(첫 점 위 40mm)에서는 도달 띠가 반경 약 76~238mm로 좁다. REQ-030(`plan_goto` 여러 시드)이 합쳐진 뒤, 벤치마크에 세 안을 옵션으로 붙여 숫자로 비교하고 기획이 정한다(결정 0037): (가) 호버 높이 낮추기, (나) `check.tool_reach_mm`를 호버 기준으로 줄이기, (다) 닿지 않는 첫 점을 경로 안쪽으로 당기기. 정해지면 `ultrasonic-spec.md` 6절과 1절을 고친다.

### D. 수동 입력·작업대 좌표
- **11 쓰임 보이기와 간편 조작 (1차)**: 모든 페이지 머리 제목 아래에 회색 한 줄 설명을 둔다(시작 화면 페이지 안내와 같은 문구). 수동 입력 = "센서 대신 사람이 물체 위치를 알려 주는 인식 방식입니다. 작업 공간 자동 실행이 이 물체들을 집습니다." 작업대·좌표 = "팔 받침, 배출 구역, 센서가 작업대 어디에 있는지 정합니다." 두 페이지에서 물체나 배치 항목을 고르면 5의 xy 패드와 돌리기 버튼으로 옮길 수 있다(누를 때마다 5mm·5°, 길게 누르면 계속). 저장은 지금처럼 따로 누른다.

### 12.2 프로그램 (작업 › 프로그램)
코드(`gui/programs.py`, `gui/pages/program.py`)가 기준이다. 저장 형식은 `system-architecture.md` 5.1.
- 단계 종류(8개): 자세로 이동(`waypoint`, 저장한 자세 이름), 좌표로 이동(`move`: x, y, 높이, yaw, pitch. 관절 공간 이동이고 직선 보장은 없다), 그리퍼(`gripper`: 값 0~100), 집어 옮기기(`pick_place`: 집기 점·크기·각도·높이와 놓기 점을 한 단계로), 대기(`wait`), 홈(`home`), 교시 재생(`replay`: 교시 이름, 배속), 반복(`repeat`).
- 정한 것: 집기·놓기는 **한 단계**로 둔다(따로 두면 물체를 든 채 다른 단계가 끼어 안전 검사가 어렵다). **직선 이동은 넣지 않는다**(팔 API에 직교 직선 보간이 없다. 필요해지면 REQ로). 홈·교시 재생은 넣는다(됨).
- 제한: 반복 횟수 1~1000, 반복 안에 반복 없음(한 겹), 대기 0~600초. 저장·실행 전에 `validate`가 검사하고 첫 문제를 "N번 단계: 이유"로 보인다.
- 순서 바꾸기는 단계마다 [위로] [아래로] 버튼(끌기는 하지 않는다). 단계를 고르면 오른쪽 칸에서 값을 고친다.
- 위: [실행] [한 단계씩] [정지], 한 단계씩이면 [다음 단계]. 실행 방식은 상단 선택을 따르고, 프로그램 전체를 팔 동작 하나로 만들어 실행 방식·안전 검사를 그대로 쓴다. 실행 중 지금 단계를 강조한다.
- 자세 목록(왼쪽 또는 좁으면 아래): 저장한 자세, 즐겨찾기 별, [이동], 삭제, [지금 자세 저장]. 자세 이름 바꾸기와 자세 3D 미리보기는 **나중**(지금은 지우고 다시 저장).

### 12.3 캘리브레이션 마법사 (장치 › 팔 › 캘리브레이션) — 신규, 두 번에 나눔
`calibrate --auto --measure-only`, `--save`, `--verify-zero`(결정 0028·0029, REQ-016·017)를 단계 화면으로 감싼다. 실제 팔에서만 켜지고, 시뮬레이션에서는 단계 설명만 보인다.

**나눠 만들기**(6절 "나중"의 조건과 맞춘다)
- **1차(지금 만들 수 있음)**: 1 준비 › 2 측정 › 3 비교. EEPROM에 쓰지 않는 측정만(`measure_only`, main에 있음)이라 실물 시험 전에도 안전하다.
- **2차**: 4 저장 › 5 0° 확인. `--save`의 `yes`·3회 중앙값과 `--verify-zero`·잠금은 REQ-017(PR #41, 합치기 대기)에 있다. #41이 합쳐지고 AC4 실물 시험이 합격한 뒤 만든다. 그 전에는 4·5단계 자리에 "AC4 실물 시험 뒤 열립니다"와 CLI 명령을 보인다.

**실행 방식과 포트**: 서브프로세스가 아니라 GUI Backend 안에서 부른다. linkwatch와 같은 방식이다(`Backend._run_linkwatch`). 측정은 `ArmService`를 거치지 않으므로(connect가 서보에 PID·가속을 씀, REQ-016) 시작할 때 팔 연결을 끊고 포트를 직접 열어 `measure_only`를 돌린 뒤, 끝나거나 중단되면 다시 연결한다. 그동안 다른 움직이는 버튼은 잠기고, 실행 중인 작업·교시·재생이 있으면 시작하지 않는다. 0° 확인(5)은 `ArmService`의 `unlock_for_verification()`·`relock_zero()`를 쓴다(#41).


| 단계 | [다음]이 켜지는 조건 | [중단]·[다름]의 결과 |
|---|---|---|
| 1 준비 | 체크 세 개 모두, 실제 팔 연결됨, 팔 `idle`, 실행 중인 작업 없음, 지금 전압 11.0V 이상 | 아무것도 하지 않음 |

### 12.7 숫자 입력 (결정 0055, 2026-11-13 초안 9 — EGM Stage 9 1~8차 지적 반영)
숫자 칸마다 허용 범위·추천 범위·기본값을 보이고, 값의 성격에 맞는 입력 방식을 쓴다. 근거 결정: 0055(값 정보표·입력 방식 규칙), 0054(화면 시험), 0014(서보 가속 10·50Hz), 0019(교시 구간 기준), 0033(그리퍼 조임). 2026-11-12 사용자 결정: 파라미터의 **[기본값으로]는 설정 파일 값**(코드 기본값이 아님)으로 되돌린다. 그 밖의 칸은 표의 "기본" 열대로.

#### 12.7.1 값 정보표 `gui/param_meta.py`
- `Meta(unit: str, hard: tuple[float, float], step: float, soft: tuple[float, float] | None = None, why: str = "", widget: str | None = None, allow_none: bool = False, none_text: str = "")`, `META: dict[str, Meta]`. 키는 아래 표의 키 그대로다.
- `hard`: 받는 한계(양 끝 포함). 밖이면 막는다. `step`: 숫자 칸 화살표·휠 한 칸이자 슬라이더 눈금. `soft`: 추천 범위. 근거(`why`, 결정·측정 번호)가 없으면 두지 않는다. `widget`: 규칙(12.7.2)을 덮어쓸 때만. `allow_none`: 빈 칸이 뜻을 갖는 값(지금은 `safety.box.xy`·`safety.box.z`만, 빈 칸 = 기본 범위, `none_text`="비우면 기본 범위").
- 기본값은 표에 적지 않는다. 파라미터의 기본은 **설정 파일 값**: 앱을 켤 때 `robot.yaml` ← `config/arms/<팔>.yaml` ← `config/grippers/<종류>.yaml` ← `local.yaml`을 합쳐 읽은 값이다(`set_params`로 바꾸기 전). 이를 위해 **팔 세션 REQ**: `ArmService.__init__`에서 합친 `cfg`의 숫자 값을 복사해 두고 `get_params()`의 항목에 `saved`로 더한다. `default`(코드 기본값)는 남기되 화면은 쓰지 않는다. 파라미터가 아닌 칸은 "기본" 열대로: 좌표·물체·작업대·안전은 없음, `replay.speed`·`program.*`는 `gui/programs.py` `DEFAULTS`의 값.

#### 12.7.2 입력 방식 규칙 (위에서부터 처음 맞는 것)
1. `widget`이 적혀 있으면 그것.
2. 정해진 보기가 있는 값(`service/params.py` `CHOICES`): 보기 3개 이하는 토글, 넘으면 고르는 목록.
3. 단위가 %·열림 눈금·토크 눈금·Hz·배이고 `(hard 위 − hard 아래) / step ≤ 200`: 슬라이더 + 오른쪽 숫자 칸. 슬라이더에 `soft`를 옅은 띠로 그린다.
4. 단위가 mm·°인 좌표·물체·작업대·안전 칸(`target.*`, `obj.*`, `ws.*`, `safety.box.*`, `gripper.width_mm`, `joint.deg`): 숫자 칸 + 간격 버튼 `−10 −5 −1 +1 +5 +10`(결정 0055). 버튼은 적힌 수(mm·°)만큼 바꾸고, `hard` 밖으로 밀면 끝값에 맞춘다.
5. 그 밖(파라미터의 mm·°·°/s·°/s²·초·서보 단위): 숫자 칸만(화살표·휠 한 칸 = `step`). 간격 버튼은 두지 않는다(°/s²처럼 큰 값에서 ±1은 뜻이 없다). 결정 0055와 다른 점은 이것뿐이다.
- 하단 막대 속도(`bar-speed`)와 상단 막대 그리퍼 속도(`top-grip-speed`) 슬라이더는 자리가 좁아 숫자 칸 없이 지금 모양을 두고 `META`의 `hard`·`step`만 쓴다.

#### 12.7.3 칸 아래 줄과 [기본값으로]
- 칸 아래 한 줄: `기본 30 · 추천 5~30 · 허용 5~100 %`. 기본이 없거나 추천이 없으면 그 부분을 뺀다.
- 값이 `soft` 밖이면 칸 아래 줄 글자를 `theme.WARN`(#8a4b00)으로, 칸 테두리를 같은 색으로 한다. `hard` 밖이면 Quasar `error`(빨강 `theme.DANGER` #c62828 테두리와 "허용 5~100 밖이라 쓰지 않습니다"). 파라미터 화면의 "바꾼 값" 강조는 줄 전체 배경(#fff4d6)과 왼쪽 막대라 칸 테두리 색과 겹치지 않는다.
- 추천 띠: 슬라이더 트랙 뒤에 `soft` 구간만 `theme.ACCENT` 20% 투명도 배경을 둔다(트랙 요소의 CSS `linear-gradient`, 위치는 `hard` 기준 백분율).
- [기본값으로]: 기본이 있는 칸 옆 작은 아이콘 버튼(`restart_alt`, 툴팁 "기본값 30으로"). 누르면 칸 값만 바꾸고 적용하지 않는다. 파라미터 화면의 바꾼 값 강조·[적용]은 지금 그대로다.

#### 12.7.4 공용 부품 계약 (`pages/common.py`)
- `meta_number(key: str, value: float | None, on_change=None, *, label: str | None = None, default: float | None = None, add=None, mark: str | None = None, hard: tuple | None = None, on_valid=None) -> MetaNumber`. `mark`가 없으면 `meta-<key>`(숫자 칸), 슬라이더 `<mark>-slider`, 간격 버튼 `<mark>-m10`…`<mark>-p10`, [기본값으로] `<mark>-reset`. 기존 시험 표식(`ws-table_x`, `replay-speed` 등)은 `mark`로 그대로 넘긴다. `hard`는 `joint.deg`처럼 그때 정해지는 한계를 넘길 때(표의 `hard`보다 우선).
- `MetaNumber`: `.value`(마지막 허용 값, `float | None` — None은 `allow_none`일 때만), `.enabled`(쓰기 가능), `.set(v, quiet=False) -> bool`(코드에서 값 바꾸기. 허용 밖이면 바꾸지 않고 False. 성공하면 `quiet`가 아닐 때 `on_change(v)`를 부른다), `.valid`(지금 칸 글자가 허용 안인가), `.set_hard(lo, hi)`(그때 정해지는 한계, `joint.deg`), `.set_error(text | None)`(그 화면의 다른 오류, 예: 높이 필요. 허용 밖 오류가 있으면 그것을 먼저 보인다), `on_valid`(생성 인자, 허용 안/밖이 바뀔 때 `on_valid(ok)`. **글자가 바뀔 때마다**(입력 이벤트, 값을 보내기 전) 판정해 바뀌었으면 바로 부른다. 그래야 치자마자 누른 버튼도 바뀐 판정을 본다), `.load(v)`(저장된 값을 다시 읽어 넣기: 허용 밖이어도 그대로 보이고 `.valid`로 알리며, `on_change`를 부르지 않고 그 칸의 "처음 값"(바꾼 값 강조의 기준)도 v로 바꾼다. 파라미터 화면은 프리셋을 불러온 뒤 모든 칸을 `.load()`로 채워, [적용]이 프리셋 값을 이전 값으로 되돌리지 않게 한다). 안의 숫자 칸·슬라이더·버튼을 한 묶음으로 켜고 끈다.
- `add`가 오면 `add(MetaNumber)`로 넘긴다. `Controls.add`는 `.enabled`를 바꾸므로 `MetaNumber`가 `.enabled` 속성을 가지면 그대로 넣을 수 있다. `Controls`에는 버튼 쪽 `needs` 인자 하나만 더한다(아래).
- 허용 밖 글자: NiceGUI `min`·`max`를 주지 않는다(말없이 잘라 내지 않게). Quasar `error`·`error-message`로 보이고, `.value`는 바뀌지 않으며 `on_change`를 부르지 않는다. 그래서 버튼이 누를 때 `.value`를 읽어도 허용 값만 받는다.
- `on_change(v: float | None)`: 허용 값 하나를 받는다(이벤트 객체가 아님). 지금 이벤트를 받아 `e.value`를 읽는 곳(`table.py`, `manual.py`, `program.py`)과 인자 없는 곳(`params.py`)은 이 모양으로 바꾼다. 코드가 값을 넣던 자리(`manual.py` 3D 점·[점 처음 자리로], `table.py` 클릭·패드, `safety.py` 기본으로)는 `.set()`을 쓴다. 파라미터 화면이 프리셋을 불러온 뒤 칸을 채우는 것만은 `.load()`다(아래).
- **`on_change`를 부르는 때**: 숫자 칸은 Enter나 칸을 떠날 때(blur, Tab·클릭으로 떠나는 것 포함) 값이 바뀌었을 때만 한 번(값을 바꾸지 않고 Tab으로 지나가면 부르지 않는다. 직접 조작 그리퍼 칸에서 팔이 움직이지 않게)(글자를 칠 때마다가 아니다. 그리퍼 칸에 50을 칠 때 5로 먼저 가지 않게). 간격 버튼·[기본값으로]는 누를 때 바로. 슬라이더는 끄는 동안 숫자 칸만 따라 바꾸고 손을 뗄 때(Quasar `change`) 한 번.
- 허용 밖 글자가 남은 동안: `.valid`가 False이고 칸에 오류 문구가 보인다. **그 칸을 읽는 실행·저장·적용 버튼은 꺼진다**(보이지 않는 이전 값으로 팔이 움직이지 않게). 방법: `Controls.add(element, needs=())`에 인자 하나를 더해 `refresh()`가 `enabled = allowed and all(m.valid for m in needs)`로 켠다(지금 `refresh()`가 tick마다 다시 켜므로 여기서 함께 본다). 버튼과 그 버튼이 읽는 칸:

  | 화면 | 버튼(표식) | 읽는 칸 |
  |---|---|---|
  | 직접 조작 | [이동] 좌표 | `target.*` |
  | 직접 조작 | [이동] 관절(`joint-to`) | `joint.deg` |
  | 직접 조작 | 그리퍼 폭으로 | `gripper.width_mm` |
  | 직접 조작 | 지금 좌표를 집기 점으로·놓기 점으로(`pp-set-pick`·`pp-set-place`) | `target.*`(옮겨 담는 값) |
  | 직접 조작 | 집어 옮기기(`pp-run`) | `obj.*`와 집기·놓기 점 칸 |
  | 파라미터 | [적용] | 그 화면의 모든 칸 |
  | 안전 | [적용](모드 토글이 부르는 적용 포함) | `safety.*` |
  | 안전 | 모드 토글과 끄기 확인 창의 [확인] | `safety.*`(모드를 바꿀 때 함께 보내는 값). 토글은 버튼이 아니라 `needs`로 끌 수 없으므로, 안전 화면 `apply()`가 첫 줄에서 여유 칸과 상자 칸 여섯의 `.valid`를 본다. 하나라도 False면 "<칸 이름>: 허용 밖이라 적용하지 않습니다"를 알리고 `mode_toggle.value = state["shown_mode"]`(지금 적용된 모드)로 되돌린 뒤 끝낸다. 끄기 확인 창의 [확인]이 이것으로 거부되면 확인 창은 닫지 않는다 |
  | 작업대·좌표 | [저장](`ws-save`) | `ws.*` |
  | 프로그램 | [저장](`program-save`)·[실행]·[한 단계씩](`program-step-run`) | 그 프로그램 모든 단계의 숫자 칸 — 아래 "프로그램 화면" |
  | 교시 | [재생](`play`) | `replay.speed` |
  | 수동 입력 | 고른 물체에 이 높이(`apply-height`) | `obj.height` |
  | 수동 입력 | 작업대 클릭으로 새 물체 더하기("새 물체" 모드, 버튼 없음) | `obj.*`(각도·폭·길이·높이). 칸이 허용 밖이면 클릭을 받지 않고 "각도·폭·길이·높이를 먼저 고치세요"를 보인다. 이 클릭은 `guard`에 `needs`를 넘기지 않는다(넘기면 "고른 물체 옮기기" 모드까지 막힌다). 대신 `clicked()`의 **더하기 분기 첫 줄**에서 각도·폭·길이·높이 칸의 `.valid`를 본다. "고른 물체 옮기기" 모드는 칸을 읽지 않으므로 막지 않는다 |

  **누를 때 다시 확인**: 버튼은 타이머(0.1~0.5초)로 꺼지므로 그 사이에 누를 수 있다. 그래서 `Controls.guard(fn, needs=())`도 같은 `needs`를 받아, 누른 순간 `all(m.valid for m in needs)`가 아니면 실행하지 않고 "<칸 이름>: 허용 밖이라 실행하지 않습니다"를 알린다(지금 `guard`는 조작권·잠김·작업 실행만 본다, `common.py`). 표의 버튼은 **프로그램 행과 수동 입력 클릭 행, 안전 모드 토글 행을 빼고** `controls.add(button, needs=...)`와 `controls.guard(fn, needs=...)`에 같은 목록을 넘긴다(뺀 세 행은 각 행과 아래 "프로그램 화면"에 적은 대로 따로 본다). 지금 표에 `guard`가 없는 [집기 점으로]·[놓기 점으로](`pp-set-pick`·`pp-set-place`)도 `controls.guard(..., needs=<target 칸>)`로 감싼다. `guard`가 감싼 함수를 부를 때는 `result = fn(*args)` 뒤 `inspect.isawaitable(result)`일 때만 `await`한다(동기 처리 함수도 감쌀 수 있게, 지금 `common.py`는 늘 `await`한다).
  **프로그램 화면**: 단계 칸은 `@ui.refreshable` 안에서 다시 만들어지므로 버튼을 더할 때 정한 `needs`로는 볼 수 없다. 그래서 페이지에 `state["invalid"]: set[(단계 번호, 칸 이름)]`을 두고, 단계 칸마다 `meta_number(..., on_valid=lambda ok, k=(i, name): ...)`로 허용 밖이 되면 넣고 안으로 돌아오면 뺀다(다시 그릴 때는 비우고 새 칸이 다시 채운다). [실행]·[한 단계씩]은 `gate`에 넣고, 페이지 `tick()` 끝에서 `enabled = gate.allowed and not state["invalid"]`로 켠다. [저장](`program-save`)은 팔을 움직이지 않으므로 `gate`에 넣지 않고, `tick()` 끝에서 `save_button.enabled = not state["invalid"]`로 둔다(둘 다 그 뒤에 다른 줄이 다시 켜지 않게 `tick()` 마지막에 둔다). **누를 때**: `save()`와 `start()`는 첫 줄에서 `state["invalid"]`가 비어 있지 않으면 "<가장 앞 단계 번호>번 단계 <칸 이름>: 허용 밖이라 실행하지 않습니다"를 알리고 끝낸다. `guard`의 `needs`는 다시 만들어지는 단계 칸을 볼 수 없으므로 이렇게 따로 본다. 단계 칸은 허용 값일 때만 `state["steps"]`를 바꾸므로(`program.py`), 이 확인이 없으면 허용 밖 글자를 치고 다음 tick(0.2초) 전에 누를 때 화면에 없는 이전 값으로 팔이 움직인다. `meta_number`는 칸을 만들 때 `on_valid(지금 허용 여부)`를 한 번 부른다(파일에서 읽은 허용 밖 값도 바로 들어가게). 또 `programs.validate`가 모든 단계의 숫자 값을 `META` 한계(`target.*`, `obj.*`, `gripper.value`, `replay.speed`, `program.*`)로 보도록 넓혀, 펼치지 않은 단계나 파일에서 읽은 단계도 저장·실행 전에 막는다("N번 단계: x 허용 −600~900 밖"). `MetaNumber`에는 `on_valid(ok: bool)` 인자 하나를 더한다.
  페이지가 `refresh()` 뒤에 `enabled`를 따로 다시 켜는 곳(`manual.py:219`, `params.py:73`, `teach.py:233`, `sensors/manual_view.py:169`)은 그 식에 `and controls.valid(needs)`를 더한다(`Controls.valid(needs) -> bool = all(m.valid for m in needs)`). 시험(12.7.7)이 이 네 곳에서 허용 밖 글자일 때 버튼이 꺼지는지 본다.
 빈 칸(`None`)은 `allow_none`이 아니면 허용 밖과 같다.
- 처음 넣는 값(`workspace.yaml`, 저장된 프로그램 단계 등)이 허용 밖이면 그 값을 그대로 보이고 오류색으로 표시하며 `.valid`는 False다(위 규칙대로 버튼이 꺼진다). 3D에서 고른 점은 x·y(·높이)를 **모두 넣거나 하나도 넣지 않는다**: 먼저 셋 다 허용 안인지 보고, 하나라도 밖이면 아무 칸도 바꾸지 않고 알림 "점이 허용 범위 밖입니다"를 한 번 낸다. 안이면 `.set(quiet=True)`로 넣고 `on_change`는 한 번만 부른다.
- 프리셋은 서비스가 팔에 먼저 적용하므로(`backend.load_preset` → `set_params`) 허용 밖 프리셋을 막는 것은 12.7.6 서비스 검사다. GUI는 불러온 뒤 모든 칸을 `.load()`로 채우고(값을 다시 보내지 않고 "처음 값"도 바꿈), 허용 밖이면 그 칸이 오류색이 된다.
- 정수 값(`get_params()`의 값이 int인 파라미터, `program.count`)은 `round()`해서 넘기고 칸 형식은 `%d`.
- 시험이 부품에 닿는 법: `meta_number`는 안쪽 `ui.number`에 `meta` 속성으로 자기를 붙인다. 코드가 넣는 값은 `_one(user, "<표식>").meta.set(v)`, 사람이 치는 값은 `user.find(marker=...).type("50")` 뒤 `.trigger("blur")`로 시험한다(NiceGUI 시험 도구에서 blur가 되는지 첫 PR에서 확인, 안 되면 `.meta` 안의 blur 처리 함수를 직접 부른다). 교시 배속 표식은 지금처럼 `replay-speed`.

#### 12.7.6 서비스 쪽 검사 (팔 세션 REQ)
`set_params`는 지금 `speed_pct`·`gripper_speed_pct`만 범위를 본다. 12.7.1 표의 파라미터 행 `hard`를 서비스에서도 거부하도록 한다(`service/params.py`에 한계 표 하나, GUI `META`와 같거나 넓은 값. 속도 두 값은 지금 1~100 그대로). 0이면 위험한 것부터: `control_hz`(0으로 나눔), `record_hz`, 최대 속도·가속도·저크 6개, 조임 힘 2개, `gripper_open`, `servo_acceleration`·`gripper_acceleration`(서보에서 0이 제한 없음일 수 있어 아래를 1로).

#### 12.7.7 시험 기준
- `META`의 파라미터 키가 모두 `get_params()`에 있고, `soft`가 있으면 `why`가 비어 있지 않으며 `soft`가 `hard` 안이다.
- `META` 파라미터 `hard`가 서비스 한계 안이다(같거나 더 좁다, 팔 REQ가 합쳐진 뒤).
- `safety.joint_margin_deg`, `safety.box.z` 최소, `program.s`, `program.count`가 원본 검사 범위와 같다. 작업대 칸의 저장은 `save_workspace` 검사가 막는다(작업대 밖 받침, 여유 ≥ 짧은 변/2).
- 안전 상자의 빈 칸은 그대로 None으로 넘어가 기본 범위가 된다.
- 칸마다 `hard` 밖 값(1e7 포함)은 그림·저장·이동에 쓰이지 않는다(11-12 무작위 조작 시험에서 작업대 가로 1e7로 연결이 끊긴 버그).
- 슬라이더·숫자 칸·간격 버튼이 같은 값을 보이고, 슬라이더를 끄는 동안에는 `on_change`가 불리지 않고 놓을 때 한 번 불린다. 숫자 칸에 "50"을 칠 때 `on_change`는 blur에서 한 번(50)만 불린다.
- 허용 밖 글자가 남은 칸이 있을 때 표(12.7.4)의 버튼이 꺼진다(`manual.py`·`params.py`·`teach.py`·`manual_view.py`처럼 페이지가 다시 켜는 곳 포함). 프리셋을 불러온 뒤 [적용]은 프리셋 값을 보낸다(`.load()`). `.set()`은 성공하면 `on_change`를 부르고 `quiet=True`면 부르지 않는다. 관절을 바꾸면 `joint.deg` 한계가 그 관절의 것으로 바뀐다.
- 슬라이더 값이 `soft` 끝점(속도 5·30)과 `hard` 끝점(100)을 고를 수 있다.
- 칸에 허용 밖 값을 넣고 바로(다음 타이머 전) 버튼을 눌러도 실행되지 않는다(`guard`가 다시 확인).
- 프로그램: 펼친 단계 칸이 허용 밖이면 [저장]·[실행]·[한 단계씩]이 꺼지고, 파일에서 읽은 단계 값이 허용 밖이면 `programs.validate`가 "N번 단계: <칸> 허용 <범위> 밖"으로 저장·실행을 막는다.
- 프로그램: 단계 칸에 허용 밖 글자를 친 직후, tick 전에 [실행]·[저장]을 누르면 거부되고 알림이 뜬다(`save()`·`start()` 첫 줄 확인).
- 안전: 여유·상자 칸이 허용 밖일 때 모드 토글을 바꾸면 적용되지 않고 토글이 지금 모드로 되돌아가며, 끄기 확인 창의 [확인]은 창을 닫지 않는다.
- `guard`가 동기 함수(`save`)와 비동기 함수를 모두 감싸 TypeError 없이 부른다. [집기 점으로]·[놓기 점으로]는 `target` 칸이 허용 밖이면 실행되지 않는다.
- 수동 입력: "새 물체" 모드에서 칸이 허용 밖이면 작업대 클릭이 물체를 더하지 않고, "고른 물체 옮기기" 모드는 그대로 옮긴다.
- 파라미터 화면의 [기본값으로]는 설정 파일 값으로 바꾸고 바꾼 값 강조를 켠다(적용 전).

| ④ | 범위 원이 단계마다 줄어든다(`spread_mm`). L1·L2 뒤 중심 점, R 뒤 긴 축 선, L3·L4 뒤 결과 사각형(초록) | `us.check_estimate`, `us.check_result` |
| ⑤ | 집기·놓기(지금 그대로, F3이 되면 쥔 상자가 따라간다) | 작업 실행 이벤트 |

- 캡션(3D 위 한 줄, 설명 모드에서는 크게): "① 레이더가 돌며 거리를 잽니다 (2/3바퀴)", "② 빈 작업대와 다른 곳: 후보 3개", "③ 팔 센서로 후보 1을 지나갑니다 (L2)", "④ 위치 (212, 180), 긴 축 45°", "⑤ 집습니다".
- 작은 화면(`mini_view`)은 같은 겹을 평면도로 그린다.

**초음파 화면(F7, 센서 › 초음파)**
- 소스가 초음파(가상·실물)이면 그 소스의 `Studio.bus`에 `UltrasonicLog`를 붙인다. 수동이면 지금 "가상으로 돌리기" 화면(`Demo`)을 그대로 둔다.
- 왼쪽 평면도에 겹 고르기 여섯 개를 둔다(체크, 여러 개 켤 수 있음):
  - ① 바닥 원자료(부채꼴 점)
  - ② 팔 원자료(경로 위 점, h로 색)
  - ③ 바닥 거른 데이터(호·후보·예상 범위 원)
  - ④ 팔이 범위로 가서 잰 원자료(후보별)
  - ⑤ 합치기(범위 원이 줄어드는 순서를 겹쳐 그림, 단계 색)
  - ⑥ 최종 위치(사각형·각도·신뢰도)
- [단계 따라가기]를 켜면 지금 단계의 겹만 켠다.
- 오른쪽 위: 레이더 각도별 거리 그래프(이번 바퀴, 기준값, 뺀 값 세 줄).
- 오른쪽 아래: 팔 센서 그래프(구간 위치 → h, 구간별 색, `hit_mm` 선).
- 아래: 후보별 타임라인 표(후보 → L1 → L2 → R → L3·L4 → 결과, 칸마다 중심·범위 mm, 시간). 지금 결과표는 마지막 열로 합친다.
- 실행이 끝나도 마지막 실행의 기록을 남겨 다시 볼 수 있다([지우기]까지).
