# GUI 설계서

상태: 초안 · 2026-11-02

근거 결정: `decisions/0020`(API 동결과 GUI 첫 작업), `0022`(디자인 도구), `0023`(NiceGUI 앱 틀 + Viser 3D, 센서별 화면). 화면 구성의 모티브는 PIPER Studio(WeGo-Robotics/wego-piper-web)이다.

## 1. 원칙
- 완성형 앱이다. 발표는 이 앱을 그대로 프로젝터에 띄우고 직접 조작하며 한다. 청중 전용 기능은 넣지 않는다.
- GUI는 `ArmService`, `Studio`, `PerceptionSource`만 호출한다. 팔과 센서를 직접 다루지 않는다.
- 센서는 끼워 넣는다. 인식 방식마다 자기 페이지와 작업 공간용 작은 화면을 등록하고, 앱은 등록된 것만 메뉴에 붙인다.
- 모든 페이지에 공통 틀이 있다. 위쪽 상태줄, 왼쪽 사이드바, 오른쪽 아래 E-STOP, 아래쪽 상태줄이다.

## 2. 공통 틀
| 영역 | 내용 |
|---|---|
| 위쪽 상태줄 | 앱 이름, 팔(시뮬레이션/실제), 연결된 센서, 실행 방식, 전압, 최고 온도, 속도, 조작권 |
| 사이드바 | 5개 그룹(3절). 접을 수 있다 |
| 페이지 머리 | 제목, 상태 배지(대기/실행 중/정지/오류), 오른쪽에 그 페이지의 주요 버튼 |
| E-STOP | 모든 페이지 오른쪽 아래에 빨간 원형 버튼으로 고정. `ArmService.estop()` |
| 아래쪽 상태줄 | 손끝 좌표, 닿는지 여부와 오차, 안전 모드, 토크, 기록 폴더 |
| 조작권 | 처음 접속한 브라우저만 조작할 수 있고, 나머지는 보기 전용이다. 조작하던 브라우저의 연결이 끊기면 `stop()` |

## 3. 페이지 (5개 그룹, 13개)
| 그룹 | 페이지 | 핵심 내용 | 주로 쓰는 API |
|---|---|---|---|
| 작업 | 작업 공간 | 진행 막대(준비 → 스캔 → 판단 → 집기 → 놓기 → 다시 스캔), 3D와 센서 화면을 나란히, 물체 목록, 관절 막대, 최근 이벤트. 버튼: 스캔, 한 단계, 자동 실행, 일시정지, 정지 | `Studio.start/step/stop`, 인식 `scan`, `status_stream` |
| 작업 | 직접 조작 | 3D(손끝 끌기 손잡이, 작업대 클릭으로 점 찍기, 시점 위/앞/옆), 관절·직교 조그(간격 1/5/10 또는 누르는 동안), 좌표 이동(미리보기 → 이동, 닿지 않으면 이유 표시), 그리퍼(값/폭), 속도 | `jog`, `point_pose`, `preview_tool`, `move_tool`, `set_gripper`, `set_speed`, `home`, `park` |
| 작업 | 교시 | 기록 목록, 새 기록 단계 안내(홈 → 잡기 → 카운트다운 → 기록), 손끝 궤적(구간 색), 구간 막대에서 구간별 배속, 전체 배속, 한계까지 재생, 관절-시간 그래프 | `record_start/stop/info`, `replay` |
| 인식 | 초음파 A·B | 작업대 평면 2D(부채꼴, 지금 각도 선, 거리 점, A·B 교차선, 닿는 범위), 각도-거리 그래프 2개(빈 작업대 기준선, 튀는 곳), 스캔 설정, 결과와 원자료 | `UltrasonicSource.calibrate/scan` (3단계) |
| 인식 | 카메라 | 자리만 둔다. 카메라 소스를 등록하면 영상, 검출 박스, 작업대 좌표 변환 화면이 생긴다 | (4단계) |
| 인식 | 수동 입력 | 작업대 평면에서 클릭으로 물체 추가·이동, 물체 표, 실행 중 추가 | `ManualSource`, 실행 중 물체 추가(0020) |
| 장치 | 팔 | 서보 6개 표(위치, 온도, 부하, 응답), 전압과 전류, 진단 버튼(servoinfo, linkwatch, powertest, shaketest. 큰 동작은 확인 창) | `connect`, `status`, 진단 함수 |
| 장치 | ESP32 센서 보드 | 포트, 펌웨어 버전, 보드가 알려 주는 센서 목록과 상태, 주고받은 JSON 메시지 | (3단계) |
| 설정 | 파라미터·프리셋 | 카드 4개(움직임, 집기, 교시, 실행 방식). 값마다 설명 한 줄, 바꾼 값 강조, 적용 시점 표시(바로 / 다음 동작부터 / 재시작). 프리셋 저장·불러오기 | 새 API(5절) |
| 설정 | 안전 | 모드(보통/자유/끔, 끔은 확인 창과 빨간 배지), 관절 여유, XYZ 허용 상자(3D에 반투명 표시), 항상 켜진 검사 목록 | `get_safety`, `set_safety` |
| 설정 | 작업대·좌표 | 위에서 본 작업대에서 팔 받침, 배출 구역, 센서 위치를 끌어서 배치, 숫자 입력, 실측 전 값 배지 | `workspace.yaml` 읽기·쓰기 |
| 시스템 | 실행 기록 | `runs/` 목록, 이벤트 시간줄, 전압·온도 그래프, 3D 다시 보기 | 파일 읽기 |
| 시스템 | 로그 | 수준 필터, 검색, 실시간 표시 | |

## 4. 화면 요소 규칙
- 3D(Viser): 실제 팔(불투명), 계산 자세(반투명 보라), 손끝 경로(점선), 작업대, 물체, 배출 구역, 허용 상자, 좌표축(작업대/로봇/툴).
- 센서 2D 화면과 3D는 같은 작업대 좌표(mm)를 쓴다. 한쪽에서 고른 물체는 다른 쪽에서도 강조된다.
- 실행 방식(동시 / 시뮬레이션 먼저 하고 확인 / 시뮬레이션만 / 실제만)은 파라미터 페이지에서 고르고 위쪽 상태줄에 늘 보인다.
- 디자인 규칙(색, 글자, 간격, 밝은/어두운 테마)은 design-system 단계에서 이 절에 추가한다.

## 5. 새로 필요한 API (0020 동결 이후 추가분)
| API | 용도 | 비고 |
|---|---|---|
| 인식 방식 선택·스캔, `Studio.step()`, 실행 중 물체 추가 | 작업 공간, 수동 입력 | 0020에서 정한 첫 작업 |
| `get_params()` / `set_params(changes)` | 파라미터 페이지. 값마다 적용 시점을 돌려준다 | 프리셋은 `config/presets/<이름>.yaml` |
| 시뮬레이션·실제 실행 방식 | 동시 / 시뮬레이션 먼저 / 시뮬레이션만 / 실제만 | 구조는 세부 설계에서 정한다 |
| 센서 화면 등록 | 인식 방식이 자기 페이지와 작은 화면을 앱에 등록 | GUI 쪽 등록부 |
| 진단 함수 | CLI의 `powertest` 등을 GUI 버튼에서 부를 수 있게 | 결과를 화면에 돌려준다 |

## 6. 남은 일 (기획)
- 기능명세서(`features.md`)와 맞추기: 실험 그룹(시험 조건·정답 입력 F3, 비교 리포트 F4), CSV 내보내기(F2), 집기·놓기 시험(B5)을 메뉴에 어떻게 넣을지 정한다. 정한 뒤 `features.md`의 옛 메뉴트리를 이 문서로 대체한다.
- design-system(색, 글자, 간격, 테마), ux-copy(버튼·안내 문구), accessibility-review(프로젝터 대비)
- 실행 방식과 조작권의 내부 구조, 폴더 구조, 작업 순서와 완료 기준, design-handoff로 인계 문서 마무리
