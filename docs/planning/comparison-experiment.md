# 초음파·카메라 인식 비교 실험 계획

상태: 초안 · 갱신 2026-10-31 · 2026-11-14 총정리(카메라 기종·방식과 일정 반영) · 2026-11-20 12/4 전 계획을 시뮬레이션 둘로(결정 0074)

## 12/4 전 계획: 시뮬레이션 비교 둘 (결정 0074, 2026-11-20 사용자 결정)
카메라가 없고 실물 일정을 모르므로 11/23~29 비교 실험은 시뮬레이션으로 한다. 아래 "목적" 이하의 초음파·카메라 실물 비교는 카메라를 산 뒤(12/4 뒤)다.

| | (가) 초음파 인식 | (나) 집기 방식 |
|---|---|---|
| 비교 | 초음파(레이더 + 팔 확인) vs manual(정답 좌표) | 규칙 기반(스크립트 전문가) vs ACT v2 100k(`runs/train/act_pick2v2_k0clip/checkpoints/100000`) |
| 도구 | 초음파 벤치마크(결정 0037, 가상 ESP32, 실제 `radar.py`·`check.py`) | MuJoCo 시험장 `mujoco_bench --suite collect_pick2 --clock step`(결정 0062·0071) |
| 조건 | 고정 시나리오 `demo`·`demo80`·`single`·`spread120`, 씨앗 200개씩, 낙관·비관. 기준 그리퍼 열은 병렬 손 실제 기구학(`--reach kin --gripper parallel`, `ultrasonic-spec.md` 1절) | 씨앗 30000~30199(체크포인트 고르기·새 씨앗 확인과 겹치지 않음, `mujoco-spec.md` 13.10.4) |
| 내는 값 | 성공률, 인식 시간(평균·90%·최대), 위치 오차(중앙·90%), 방향 정답률, 작업 실행 끝까지 시간(초음파 vs manual) | 성공률, 실패 유형(`judge` 판정별 수), 에피소드 시간, 씨앗 짝 표(둘 다 성공 / 규칙만 / ACT만 / 둘 다 실패) |
| 맡는 곳 | 초음파 세션 | MuJoCo 세션 |
- 표마다 도구, 커밋, 시나리오, 씨앗 범위를 적는다(결정 0037). 결과는 `measurements.md`에 두고 `ultrasonic-spec.md` 1절 표는 (가) 값으로 바꾼다.
- **실물 열**: 실물이 오면 같은 표에 열을 더한다. (가)는 레이더 R1·팔 확인 A1·통합 I1(정답 쌍, `ultrasonic-spec.md` 8.4·8.6), (나)는 실물 팔 집기(규칙 기반, 같은 물체). 시뮬레이션 열과 섞지 않는다.

## 목적
같은 픽 앤 플레이스 작업에서 초음파 인식과 카메라 인식 중 어느 쪽이 더 나은지, 그리고 각 센서가 유리한 환경이 어디인지 확인한다.

## 통제 변인
- 바뀌는 것은 인식 모듈뿐이다. 두 인식 모듈은 같은 출력 `[{x, y, 각도, 폭, 길이, 신뢰도}]`를 낸다 (`decisions/0004`).
- 판단(우선순위, 명령 생성)과 제어(pick, place)는 같은 코드를 쓴다.
- 같은 물체, 같은 배치, 같은 작업대 좌표계에서 측정한다.
- 크기·방향 추정은 센서마다 계산법이 다르므로 인식 모듈에 속한다.

## 평가 기준
| 기준 | 측정 방법 |
|---|---|
| 위치 정확도 | 실제 위치와 추정 위치의 오차(mm) |
| 방향 정확도 | 0/45/90/135° 분류 정답률 |
| 인식 속도 | 스캔 1회에 걸리는 시간(초) |
| 집기 성공률 | 인식부터 놓기까지 끝까지 성공한 비율 |
| 비용 | 초기 비용은 BOM으로 계산. 유지보수 비용과 교체 주기는 문헌 값 인용 |
| 환경 강인성 | 아래 조건별로 정확도가 얼마나 떨어지는지 |

## 환경 조건 가설 (테스트로 확인 필요)
센서 원리에서 추린 후보다. 카메라는 빛의 반사를, 초음파는 소리의 반사를 쓴다.

### 카메라만 흔들릴 것으로 보는 조건
| 조건 | 예상 영향 |
|---|---|
| 어둡거나, 조명이 깜빡이거나, 밝기가 바뀜 | 노출 변화로 윤곽이 흐려짐 |
| 그림자, 역광, 광택면 반사 | 그림자를 물체로 오인하거나 경계를 놓침 |
| 물체 색이 배경과 같음 | 색으로 구분 불가 |
| 투명 물체 (페트병, 유리) | 거의 보이지 않음. 초음파는 감지 가능 |

### 초음파만 흔들릴 것으로 보는 조건
| 조건 | 예상 영향 |
|---|---|
| 온도 변화 | 음속이 1°C에 약 0.18% 변해 거리 오차 (20°C 차이면 약 3.5%) |
| 초음파 대역 소음 (압축공기 누설, 다른 초음파 센서) | 가짜 반향 |
| 바람, 기류 | 측정값 흔들림 |
| 흡음 재질 (스펀지, 천) | 반향이 약해 놓침 |
| 매끈한 면이 비스듬히 놓임 | 정반사로 반향이 돌아오지 않음 |
| 작거나 얇은 물체, 서로 붙은 물체 | 빔 폭(약 15°) 때문에 구분 불가 |

## 예상 시나리오
- 초음파가 유리할 장면: 어두운 곳, 조명 변화, 투명하거나 배경과 같은 색인 물체.
- 카메라가 유리할 장면: 작은 물체, 촘촘한 배치, 정밀한 각도.

## 정해진 것 (2026-11-14)
- 카메라: AI-Thinker ESP32-CAM 1대, 작업 면 위 500~700mm에서 내려다봄, Wi-Fi(노트북 핫스팟) MJPEG(결정 0058, `workbench-hardware-requirements.md` 4.1).
- 카메라 인식: OpenCV 규칙 기반(ArUco 호모그래피 + 색·윤곽 + `minAreaRect`). 카메라 하나로는 높이를 모르므로 물체 높이는 알려 준다(결정 0052·0058). 코드(`CameraSource`)는 초음파 실물 뒤.
- 일정: 비교 실험은 11/23~29(`work-queue.md` "11-12 우선순위"). 2026-11-20부터 이 주는 위 시뮬레이션 비교 둘이다(결정 0074).
- 정답 위치는 작업대 mm 그리드로 잰다(`workbench-hardware-requirements.md` 6절).
- 시뮬레이션: 초음파 쪽은 MuJoCo 시험장으로 미리 볼 수 있다(결정 0062, `mujoco-spec.md` 13.10 M6). ~~성적표 숫자는 실물만 쓴다.~~ 결정 0074로 시뮬레이션 숫자도 쓰되 "시뮬레이션" 열로 따로 적는다.
