# 레퍼런스 조사

## 원칙
근거 없이 추천하거나 구현하지 않는다. 다른 프로젝트들이 같은 문제를 어떻게 풀었는지 **최소 10개** 조사하고, 정량 점수로 비교한 뒤 결정안을 사용자에게 제안한다.

## 쓰지 않는 경우
- 오타, 이름 변경 같은 기계적 수정
- 사용자가 이번에는 조사를 생략하라고 명시한 경우

## 절차
1. **문제 정의**: 해결할 문제와 고민 요소를 3~5개 적는다.
2. **평가 기준**: 아래 기본표를 쓴다. 주제에 맞지 않는 기준이 있으면 바꾸고, 바꾼 이유를 결과에 적는다.
3. **후보 수집**: 10개 이상 모은다. 출처는 GitHub, Hugging Face(LeRobot 생태계), 공식 문서(Context7), 논문, 커뮤니티 사례로 다양하게 섞는다.
4. **채점**: 후보마다 기준별 1~5점을 매기고 총점을 낸다. 원문을 직접 읽지 못하고 2차 요약만 본 출처는 그렇게 표시하고 검증 점수를 낮춘다.
5. **비교**: 상위 3개를 비교하고, 근거들이 서로 충돌하는 부분을 정리한다.
6. **제안**: 결정안을 근거와 함께 사용자에게 제안한다. 승인받기 전에는 적용하지 않는다.
7. **저장**: CLAUDE.md의 "레포에 올리는 것" 규칙을 따른다. 조사 기록을 커밋할지는 묻고 정한다.

## 기본 평가표 (가중치 합 20, 만점 100)
| 기준 | 가중치 | 5점 | 1점 |
|---|---|---|---|
| 하드웨어 적합도 (SO-101, STS3215, ESP32) | 5 | 같은 하드웨어 | 개념만 참고 가능 |
| 문제 일치도 | 5 | 같은 문제를 해결 | 일부만 관련 |
| 유지보수 상태 | 3 | 3개월 이내 활동 | 1년 넘게 방치 |
| 최신 LeRobot 호환성 | 3 | 최신 버전에서 동작 | 구버전 전용 |
| 문서·재현성 | 2 | README만으로 재현 가능 | 문서 없음 |
| 라이선스 | 1 | MIT / Apache-2.0 | 없음 / 비상업 |
| 커뮤니티 검증 | 1 | 널리 사용됨 | 개인 실험 |

하드웨어와 관계없는 주제(문서 작성법, 도구 선택 등)에서는 하드웨어 적합도와 LeRobot 호환성 대신 **근거 수준**(통제 실험이나 공식 스펙 = 5)과 **원문 검증 여부**를 쓴다.

## 결과 형식 (필수 항목)
```
## 문제 정의
## 평가 기준 (기본표와 다르면 바꾼 이유)
## 후보 N개 — 이름 | 링크 | 기준별 점수 | 총점 | 원문 확인 여부
## 상위 3개 비교와 근거 간 충돌
## 결정안 (승인 대기) — 결정 | 근거로 삼은 후보 번호
## 버린 후보와 이유
```

## 흔한 실수
| 실수 | 바로잡는 법 |
|---|---|
| 후보 3~5개로 끝내고 "추천"한다 | 10개를 채우기 전에는 결정안을 쓰지 않는다 |
| 점수 없이 장단점만 나열한다 | 모든 후보에 기준별 점수를 매긴다 |
| 2차 요약을 원문처럼 인용한다 | 원문 확인 여부 칸을 채운다 |
| 승인 전에 CLAUDE.md나 코드에 반영한다 | 결정안은 제안으로만 둔다 |
| 조사 기록을 묻지 않고 커밋한다 | 7단계를 따른다 |
